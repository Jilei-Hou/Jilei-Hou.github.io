SmoothQuant：大语言模型的 W8A8 训练后量化

💡 一句话总结：SmoothQuant 是一种无需训练的训练后量化（PTQ）方法。它用数学等价的逐通道缩放，把激活中离群值造成的量化难度部分转移给权重，使大模型中所有矩阵乘都能用 INT8 权重和 INT8 激活（W8A8）计算。在 OPT-175B、BLOOM-176B、GLM-130B、MT-NLG 530B 以及 Llama、Falcon、Mistral 等模型上精度损失可忽略，推理最高提速 1.56 倍，显存约减半。

适合读者：了解 Transformer 结构和 FP16/INT8 基本概念、关注大模型推理部署的算法与工程同学。读完可以了解大模型激活为什么难量化、SmoothQuant 怎样解决、实验证据如何，以及它适合和不适合的场景。

论文信息

  • 标题：SmoothQuant: Accurate and Efficient Post-Training Quantization for Large Language Models
  • 作者：Guangxuan Xiao、Ji Lin（共同一作）、Mickael Seznec、Hao Wu、Julien Demouth、Song Han
  • 机构：MIT、NVIDIA
  • 发表：ICML 2023；arXiv 首版发布于 2022 年 11 月，本文依据 2024 年 3 月更新的 v7
  • 链接：论文 arXiv:2211.10438，官方代码（MIT 许可）

要解决的问题：大模型的激活难以量化

大模型推理的显存和算力成本很高。以 175B 参数的 GPT-3 为例，用 FP16 存储至少需要 350GB 显存，仅推理就要 8 张 48GB 的 A6000 或 5 张 80GB 的 A100。如果把权重和激活都量化为 INT8（记作 W8A8），显存占用可以减半，矩阵乘吞吐接近翻倍。

难点在激活。CNN 和 BERT 这类较小模型的激活容易量化，但模型参数超过 6.7B 后，激活中会出现幅值很大的系统性离群值（outlier），直接量化误差很大。论文发表时，已有方案无法同时保住精度和硬件效率。下表的准确率均为 OPT-175B 在 7 项零样本任务上的平均值，FP16 为 66.9%。

方法 做法 问题
朴素 W8A8 权重和激活都用 per-tensor INT8 量化 精度降到 35.5%，接近随机
ZeroQuant 权重按组（group-wise）量化，激活按 token 动态量化 在 GPT-J-6B 等模型上有效，但在 OPT-175B 上降到 35.8%
LLM.int8() 混合精度：离群值通道保留 FP16，其余用 INT8 精度保住了（66.7%），但混合精度难以在硬件上高效实现，多数情况下比 FP16 还慢
Outlier Suppression 非缩放 LayerNorm 加按 token 裁剪 在 BERT、BART 上有效，在 OPT-175B 上降到 36.0%

因此论文的目标是：无需训练、对硬件友好，并且让所有计算密集算子都用 INT8。

关键观察：离群值集中在少数固定通道

作者可视化了 OPT-13B 中一个量化误差较大的线性层，对比平滑前后激活和权重的幅值分布（见下图）。原始激活中少数通道的幅值超过 70，其余通道很小；原始权重则平坦均匀。

由此可以总结出以下规律：

  1. 权重容易量化，激活难。权重分布平坦，已有工作表明 LLM 权重做 INT8 甚至 INT4 量化都不会降低精度。
  2. 离群值压缩了其余通道的精度。对称 INT8 量化的步长由张量的最大绝对值决定：Δ=max⁡(∣X∣)/(2N−1−1)\Delta = \max(|X|) / (2^{N-1}-1)Δ=max(∣X∣)/(2N−1−1)。设通道 i 的最大值为 mim_imi​、整个矩阵的最大值为 mmm，在 per-tensor 量化下该通道的有效量化级数约为 28⋅mi/m2^8 \cdot m_i / m28⋅mi​/m。离群值比大多数激活值大约 100 倍，非离群通道只剩 2 到 3 个有效量化级。
  3. 离群值固定出现在少数通道。某个通道一旦出现离群值，它在所有 token 上都偏大。同一 token 内不同通道差异很大，同一通道在不同 token 之间差异很小。

为什么不直接按通道量化激活

既然离群值固定在某些通道，最直接的办法是给激活的每个通道单独设步长（per-channel 量化）。论文的模拟实验证实这样能保住精度：在 OPT-175B 上，按 WinoGrande、HellaSwag、PIQA、LAMBADA 4 项任务平均，per-channel 激活量化的准确率为 71.4%，接近 FP16 的 71.6%；per-tensor 和 per-token 量化只有 32.3% 和 31.7%。

问题在硬件。INT8 GEMM 内核（如 Tensor Core 上的矩阵乘）只能沿矩阵乘的外层维度缩放，即激活的 token 维度 TTT 和权重的输出通道维度 CoC_oCo​，并在乘法完成后统一乘回：

Y=diag(ΔX)⋅(XˉINT8⋅WˉINT8)⋅diag(ΔW)Y = \mathrm{diag}(\Delta_X) \cdot (\bar{X}^{\mathrm{INT8}} \cdot \bar{W}^{\mathrm{INT8}}) \cdot \mathrm{diag}(\Delta_W)Y=diag(ΔX​)⋅(XˉINT8⋅WˉINT8)⋅diag(ΔW​)

激活的通道维度 CiC_iCi​ 恰好是矩阵乘内部求和的维度，不能在这里使用逐通道的步长，所以 per-channel 激活量化无法使用高效的 INT8 GEMM。已有方法只能退而使用 per-token 激活量化，效果只比 per-tensor 略好。

方法：把量化难度从激活迁移到权重

激活难量化而权重容易量化，SmoothQuant 就在离线阶段把激活中各通道的尺度差异转移一部分给权重。平滑后的激活 X^\hat{X}X^ 和调整后的权重 W^\hat{W}W^ 都容易量化，两者都可以用 INT8 表示。

平滑变换

对线性层 Y=XWY = XWY=XW，为每个输入通道 jjj 选一个平滑因子 sjs_jsj​，把激活按通道除以 sss，同时把权重对应的行乘以 sss：

Y=(X diag(s)−1)⋅(diag(s) W)=X^W^Y = (X\,\mathrm{diag}(s)^{-1}) \cdot (\mathrm{diag}(s)\,W) = \hat{X}\hat{W}Y=(Xdiag(s)−1)⋅(diag(s)W)=X^W^

输出在数学上完全等价。它与 per-channel 激活量化的区别在于：逐通道缩放发生在量化之前，并且离线完成。diag(s)−1\mathrm{diag}(s)^{-1}diag(s)−1 可以融合进前一层（如 LayerNorm 或线性层）的参数，diag(s)\mathrm{diag}(s)diag(s) 直接乘进当前层权重，运行时不增加任何算子；量化本身仍是 per-tensor 或 per-token，可以直接使用 INT8 GEMM。若输入来自残差相加，则在残差支路上额外加一次缩放。

迁移强度 α

平滑因子 sss 的取法决定难度如何分配，两种极端都不可取：

  • 取 sj=max⁡(∣Xj∣)s_j = \max(|X_j|)sj​=max(∣Xj​∣)：平滑后激活每个通道的最大值都是 1，激活最容易量化，但难度全部转给了权重，权重量化误差变大，精度明显下降。
  • 取 sj=1/max⁡(∣Wj∣)s_j = 1 / \max(|W_j|)sj​=1/max(∣Wj​∣)：难度全部留在激活上，同样掉点。

论文用超参数迁移强度 α\alphaα 在两者之间折中：

sj=max⁡(∣Xj∣)αmax⁡(∣Wj∣)1−α,j=1,2,…,Cis_j = \frac{\max(|X_j|)^{\alpha}}{\max(|W_j|)^{1-\alpha}}, \quad j = 1, 2, \ldots, C_isj​=max(∣Wj​∣)1−αmax(∣Xj​∣)α​,j=1,2,…,Ci​

α=0.5\alpha = 0.5α=0.5 时，同一通道上激活和权重的最大值相等，两边各分担一半难度。下图是一个数值例子：激活 XXX 各通道的最大绝对值为 [2, 16, 2, 9]，权重 WWW 各行的最大绝对值为 [2, 1, 2, 1]，算得 sss = [1, 4, 1, 3]。平滑后激活各通道和权重各行的最大值都变成 [2, 4, 2, 3]，激活的整体最大值从 16 降到 4，权重的最大值只从 2 升到 4。

论文中使用的 α\alphaα：

  • OPT 和 BLOOM 全系列：0.5。
  • GLM-130B：0.75。它的离群值约占 30%，激活更难量化，需要把更多难度迁移给权重。
  • LLaMA：0.8；Llama-2：0.85 到 0.9；Falcon：0.6 到 0.7；Mistral 和 Mixtral：0.8。

在 OPT-175B 的 LAMBADA 任务上，α\alphaα 取 0.4 到 0.6 时精度接近 FP16；α\alphaα 小于 0.4 时激活难量化，大于 0.6 时权重难量化，两侧精度都会大幅下降。

离线处理流程

  1. 校准：从 Pile 数据集中随机取 512 条句子输入模型，统计需要平滑的线性层输入激活在各通道上的最大绝对值 max⁡(∣Xj∣)\max(|X_j|)max(∣Xj​∣)。
  2. 选定 α\alphaα（论文在 Pile 验证集的子集上做快速网格搜索），按上式计算每层的平滑因子 sss。
  3. 把 diag(s)−1\mathrm{diag}(s)^{-1}diag(s)−1 融合进前一层的参数，把 sss 乘进当前层权重。
  4. 把平滑后的权重量化为 INT8；若采用静态激活量化，同时用校准数据确定激活的量化步长。
  5. 推理时用 INT8 GEMM 内核直接计算。同一个量化后的模型用于所有下游任务，不针对任务重新校准。

在 Transformer 中的应用

线性层占了大模型绝大部分参数和计算量。SmoothQuant 默认对自注意力层和前馈层（FFN）的输入激活做平滑，并让所有线性层（Q/K/V 投影、输出投影、FC1、FC2）和注意力中的两个批量矩阵乘（BMM）都用 INT8 计算；LayerNorm、Softmax 等轻量算子保持 FP16，以兼顾精度和效率。

三档量化配置 O1 到 O3

SmoothQuant 不绑定具体的量化粒度，论文给出由准到快的三档配置，权重和激活均为 INT8。静态量化用校准数据离线确定激活步长，动态量化在运行时按实际激活计算步长。下表延迟为 PyTorch 实现在单张 A100 80GB、批大小 4 时测得。

实验结果

实验覆盖 OPT、BLOOM、GLM-130B 和 MT-NLG 530B，后续版本补充了 LLaMA、Llama-2、Falcon、Mistral、Mixtral 以及指令微调模型 OPT-IML。精度评测使用 LAMBADA、HellaSwag、PIQA、WinoGrande、OpenBookQA、RTE、COPA 共 7 项零样本任务和 WikiText 困惑度；由于部分任务出现在 GLM-130B 的训练集中，GLM-130B 改用 LAMBADA、MMLU、MNLI、QNLI。对比基线为朴素 W8A8、ZeroQuant、LLM.int8() 和 Outlier Suppression。实现基于 PyTorch（Hugging Face）和 FasterTransformer，INT8 算子使用 CUTLASS INT8 GEMM，硬件为 NVIDIA A100 80GB。

精度：基线崩溃，SmoothQuant 与 FP16 持平

OPT-175B 的激活最难量化。朴素 W8A8、ZeroQuant 和 Outlier Suppression 的结果接近随机；LLM.int8() 靠 FP16 表示离群值保住了精度，但延迟开销大；SmoothQuant 三档配置都与 FP16 基本持平，最激进的 O3 也不例外。

补充说明：

  • OPT 各个规模的模型在 O3 配置下都与 FP16 精度一致。
  • BLOOM-176B 比 OPT-175B 容易量化，朴素 W8A8 也只掉 4 个百分点；SmoothQuant 的 O3 档下降 0.8 个百分点，作者归因于离线校准统计与真实样本激活的差异。

  • LLaMA 系列的激活离群值没有 OPT、BLOOM 严重，SmoothQuant 同样适用。

局限与适用边界

  • α 需要按模型调。不同模型的合适 α\alphaα 从 0.5 到 0.9 不等，超出合适区间精度会大幅下降，需要用校准数据做一次搜索。
  • 静态量化依赖校准数据。O3 最快，但在 BLOOM-176B、GLM-130B 上有 0.8 到 1 个百分点的下降；精度要求高时可以退到 O1 或 O2。
  • 只覆盖 8 比特。论文只做了 W8A8。作者认为与 GPTQ 等权重量化方法结合有望实现 W4A4，但留作未来工作。
  • 与只量化权重的方法侧重不同。作者在附录中指出，批大小为 1 的生成主要受显存带宽限制，GPTQ 这类只量化权重的方法可能更有优势；SmoothQuant 更适合批量推理和上下文阶段，这时一次处理的 token 多，INT8 GEMM 的算力优势更明显。激活量化还有助于降低长上下文、大批量场景下 KV cache 的显存占用。
  • 加速依赖 INT8 硬件支持。论文的速度数据都在 NVIDIA A100 80GB 上测得，换用其他硬件时，收益取决于该硬件的 INT8 矩阵乘性能。

ModelOpt 中的 SmoothQuant 实现

💡 本章面向源码：梳理 TensorRT-Model-Optimizer（PyTorch 路径，ModelOpt 中没有对 ONNX 实现的 SmoothQuant）中 SmoothQuant 的调用链路、算法本体与支持算子。核心代码集中在三个文件。

文件 角色
quantization/model_calib.py（smoothquant()） 算法本体：收集统计、计算平滑因子、折叠进权重
quantization/config.py（SmoothQuantCalibConfig） 配置类，定义 alpha 超参
quantization/mode.py（SmoothQuantModeDescriptor） 把算法名 smoothquant 注册为一个 calibrate mode

调用链路

算法本体三步走

对每个满足条件的量化线性层，smoothquant() 执行三步：

第一步：per-channel 收集激活统计

先把 input_quantizer.axis 设为 -1（按输入通道），跑校准数据 max_calibrate，得到每个输入通道的激活幅度 act_amaxact\_amaxact_amax。

第二步：计算平滑因子

scale_a=max⁡(∣W∣)1−α/max⁡(∣X∣)αscale\_a = \max(|W|)^{1-\alpha} / \max(|X|)^{\alpha}scale_a=max(∣W∣)1−α/max(∣X∣)α

随后把激活量化器切回 per-tensor（axis=None），原 per-channel amax 存入 _amax_for_smoothing 备用。

第三步：落地——施加并折叠

激活侧设 pre_quant_scale = scale_a；权重侧 weight *= 1/scale_a 直接折叠进 weight.data，再重算权重 amax。

❗ 注意符号方向：论文的平滑因子 sj=max⁡(∣Xj∣)α/max⁡(∣Wj∣)1−αs_j = \max(|X_j|)^{\alpha}/\max(|W_j|)^{1-\alpha}sj​=max(∣Xj​∣)α/max(∣Wj​∣)1−α 是「激活除以 sss、权重乘以 sss」。ModelOpt 计算的 scale_ascale\_ascale_a 是论文 sss 的倒数，作为 pre_quant_scale 乘到激活（等价于除以 sss），权重再乘 scale_ascale\_ascale_a 的倒数——数学上与论文完全一致。

工程细节上还做了：张量并行同步（column-parallel 层对 act_amaxact\_amaxact_amax、weight_scaleweight\_scaleweight_scale 做 all-reduce MAX，保证 TP 组内 pre_quant_scale 一致）、零通道保护（amax 接近 0 的通道把 scale 置 1）、以及数值钳制 scale_a∈[10−4,104]scale\_a \in [10^{-4}, 10^{4}]scale_a∈[10−4,104]，防止溢出。

支持的算子

SmoothQuant 遍历模型时，唯一的筛选条件是 is_quantized_linear(module)。该判定的核心要求是：模块是量化模块、含 input_quantizer / weight_quantizer，且权重必须是 2D（GEMM / Linear 类算子）。

✅ 支持：所有 2D 权重的 Linear / GEMM 类模块

  • PyTorch 原生 nn.Linear
  • Megatron：Column / RowParallelLinear（含 TE 版本）
  • Transformer Engine：te.Linear、GroupedLinear、LayerNormLinear
  • vLLM：Row / Column / QKVParallelLinear
  • HuggingFace：HFColumn/RowParallelLinear、FalconLinear、FP8Linear 等
  • apex / fairscale / peft（LoraLinear）/ PyG Linear

❌ 不支持（校准时跳过）

  • nn.Embedding——代码硬编码排除（虽是 2D 权重但非 GEMM）。
  • 所有 Conv / ConvTranspose（1d/2d/3d）——它们能被量化，但权重为 3D/4D/5D，weight.dim()==2 不成立，SmoothQuant 直接跳过、不做平滑。

此外，即便是 Linear，运行期还有三道 warn-and-skip 关卡：必须已校准、仅 INT8（input/weight num_bits 均为 8）、且为 per-channel（axis=-1）且通道数 > 1，否则该层被跳过。

💡 与其他实现区分：某些内部 ONNX 路径的 SmoothQuant 实现支持 Linear / Conv / ConvTranspose / Gemm，并专门处理 group conv。但本仓库的 PyTorch 实现仅支持 2D 权重的 Linear / GEMM 类算子，不含任何 Conv，两者算子范围不同，不可混用。

配置与预设

配置类 SmoothQuantCalibConfig 只有一个超参 alpha：

项 说明
method 固定 "smoothquant"
alpha 迁移强度，范围 [0, 1]；ModelOpt 默认 1.0（注意：不同于论文常用的 0.5）。α=1.0\alpha=1.0α=1.0 时 scale_a=1/act_amaxscale\_a = 1/act\_amaxscale_a=1/act_amax，把全部难度迁往权重。

开箱预设 INT8_SMOOTHQUANT_CFG（configs/ptq/presets/model/int8_smoothquant.yaml）：权重 per-channel INT8（axis=0）+ 激活 per-tensor INT8——正是 SmoothQuant 的目标形态，平滑因子让 per-tensor 激活也能精确量化。
