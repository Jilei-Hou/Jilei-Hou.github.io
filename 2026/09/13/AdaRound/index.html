AdaRound

概要

过往的模型量化研究，核心点都是如何寻一个更优的 scale 值使得量化后的模型精度更高。而高通在论文《Up or Down? Adaptive Rounding for Post-Training Quantization》中提出了一种名为 AdaRound 的后量化算法，该算法的关注点不再是如何为每个 kernel / channel / tensor 寻找更好的 scale，而是从数学的角度分析量化过程中的 round-to-nearest 操作，并最终得出结论：看似很符合直觉的 round-to-nearest 其实并不是精度最优的。针对这个发现，作者提出 AdaRound，一种自适应的 round 后量化算法。从论文实验结果来看，针对多个 CV 模型，AdaRound 可以在不需要 QAT 或 finetune 的情况下，仅使用少量无标签的校准数据在精度上达到 SOTA，甚至 4bit 量化也可以保留较好的精度。

就整篇论文的结构来看：该论文首先从数学的角度证明了在模型量化中，直接将浮点数进行四舍五入 round 到最近定点数的方法并不是精度最优的，并且通过一个简单的实验证实了这个猜想。然后作者通过一系列的数学推导和先验假设，得到了 AdaRound 算法，并通过一系列消融实验和对比实验验证了该算法的优越性。

AdaRound 算法一言以蔽之：对 conv 中每个 weight 值进行量化时，不再是四舍五入的 round-to-nearest，而是自适应地决定 weight 量化时将浮点值转到最近的右定点值还是左定点值。（例如根据 round-to-nearest 规则，4.3、4.5、4.7 会分别转到定点值 4、5、5，而 AdaRound 则可能将其转换为 5、4、4 的定点值）。

二、背景

量化指的是将一个范围的浮点值转换成定点值，常规的模型量化流程是：

  1. 先根据量化算法计算 scale 值。
  2. 浮点值除以 scale 后进行 round 操作。
  3. 最后再按照定点取值范围进行 clip，得到量化定点值。

而如果对量化产生的定点值再乘个 scale（该过程也被称为反量化），得到的就是伪量化值，记做 W^\hat{W}W^（虽然又回到了浮点值，但由于量化过程中有 round 和 clip 操作，伪量化值已经不同于原始浮点值）。整个反量化过程如公式 (1) 所示：

五、AIMET 中的 AdaRound 工程实现

✅ 推荐场景： AdaRound 能把难量化模型恢复到接近 FP32 的水平，甚至支持把权重压到 INT4。以下以高通开源量化工具 AIMET 的 ONNX 实现为例，梳理其工程落地方式。

AIMET 的 aimet_onnx.apply_adaround 会冻结量化范围（delta / offset）（delta 就是 scale，offset 就是 zero point），只把「每个权重向上还是向下取整」变成一个可学习参数 alpha，再逐层跑上万步梯度下降学出最优取整方向。核心分四步：

  1. 参数化取整：用 floor + h_alpha 代替 round。h_alpha∈[0,1]h\_alpha \in [0,1]h_alpha∈[0,1]，0 = 向下取整、1 = 向上取整，中间是可微软插值，因而能对 alpha 求梯度。
  2. rectified sigmoid：把 alpha 映射到略超出 [0,1][0,1][0,1] 再截断（GAMMA=−0.1、ZETA=1.1），使 h_alphah\_alphah_alpha 能真正取到 0 和 1 两端，而普通 sigmoid 到不了端点。
  3. alpha 初始化：反解出让初始 h_alphah\_alphah_alpha 恰好等于权重小数部分的 alpha，保证学习起点等价于就近取整，只学「偏离量」。
  4. 逐层顺序优化：按计算图 ordered_ops 顺序逐层处理，共享权重节点跳过；每层收敛后冻结其权重 encodings。

目标函数 = 重建损失 + 取整正则（adaround_loss.py）。重建损失让量化层输出贴近原始 FP32 层输出（需校准数据采集每层真实输入激活）；取整正则把 h_alphah\_alphah_alpha 推向 0 / 1，避免停在 0.5 的模糊地带。

迭代过程按退火调度分两阶段：

阶段 迭代区间 行为
Warm start 前 20% 只有重建损失，取整正则=0；alpha 自由探索，先把层输出误差降下来
退火收敛 后 80% 加入取整正则，beta 按余弦调度让正则曲线越来越尖，把每个 h_alphah\_alphah_alpha 逼向 0 或 1

关键疑问：ONNX 模型不可导，怎么迭代 h_alpha？

onnxruntime 是纯推理引擎、不做反向传播，那 alpha 的梯度从哪来？答案是：AdaRound 的反向传播根本不在 onnxruntime 里，而是搬到 PyTorch 上做。一个 ONNX 量化库的优化器文件（adaround_optimizer.py）顶部却 import 了 torch，正是这个原因：

它把职责拆开，onnxruntime 只负责「取数据」，PyTorch 负责「算梯度」：

职责 由谁完成
提供该层的输入激活、FP32 参考输出 onnxruntime（前向，无梯度）
用该层运算重建前向（conv / linear / matmul） PyTorch functional（可微）
对 alpha 反向传播、Adam 更新 PyTorch autograd + optimizer
优化完成后把学到的取整写回权重 更新 ONNX 模型 weight 张量

取什么 来自哪个模型 在反向传播里当什么
该层输入激活 量化 sim 模型 前向输入 x（喂给 PyTorch 重建的 conv / linear）
该层 FP32 输出激活 FP32 原始模型 重建损失的 target y（干净的标准答案）

💡 说明： 输入 x 取自量化模型（已带前面各层的量化误差），输出参考 y 取自FP32 模型（干净）。于是优化目标变成「在带误差的量化输入下，让本层输出尽量逼近 FP32 干净输出」——本层顺便补偿前面层累积的误差。这也是 AdaRound 必须严格按层先后顺序逐个处理的原因：前面层定下来后，后面层采到的输入激活才准确。
