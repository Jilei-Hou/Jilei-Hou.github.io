GPTQ：大模型的 3-4 Bit 训练后量化

本文对 GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers（arXiv:2210.17323，发表于 ICLR 2023）进行解读。GPTQ 提出一种基于近似二阶信息、可在一次内完成权重量化的后训练量化（PTQ）方法，使 OPT-175B、BLOOM-176B 这类约 1750 亿参数规模的生成式模型也能压缩至每权重 3-4 Bit，同时保持接近全精度（FP16）的精度。

一句话结论： 千亿级 GPT 模型可以做到低成本、高精度的一步式量化——无需微调，仅用少量通用文本校准，即可把模型压缩到 3-4 Bit 位宽；175B 模型 4 Bit 时 perplexity 仅比 FP16 高约 0.1，3 Bit 时约高 0.3-0.6；3 Bit 量化后的 OPT-175B 可放入单张 80GB A100，生成速度约为 FP16 的 3.25 倍。

千亿级模型为何需要 GPTQ

Transformer 系生成预训练模型在复杂语言建模任务上取得突破性表现，但随参数规模膨胀，计算与存储成本也水涨船高。GPT-3 级别的模型（GPT3-175B，约 1750 亿参数）即在 FP16 下占 326GB 存储，超出最高端单卡 GPU 的容量，推理只能依赖多卡部署，难以被广泛使用。

模型压缩（剪枝、量化）被提出缓解成本，但此前高精度压缩方案多要求重新训练或微调，难以扩展到十亿参数级别；后训练量化（PTQ）则无需重训练，为大模型压缩提供了新思路。此前能保持较高精度的 PTQ 方法（如 AdaRound、BRECQ、OBQ）尚未在千亿参数规模得到验证，更基础的后训练直接取整（RTN，如 LLM.int8、ZeroQuant、nuQmm）在 175B 上 4 Bit 精度明显下降、3 Bit 基本崩溃。GPTQ 的目标，是填补这一空白：用一次性 PTQ 实现高精度、高效率的 3-4 Bit 量化。

训练感知量化 训练时 是 已验证至百亿级 有方案，但工程成本高

GPTQ 的核心思想：基于二阶信息的一次性量化

GPTQ 是一种新的一次性后训练权重量化方法，基于近似二阶信息，既高效又高精度。对每个 Transformer 线性层，GPTQ 求解量化权重 W^\hat{W}W^，使层输出平方误差最小；量化网格（scale / zero point）固定，权重可自由落点。由于误差可按权重矩阵的行拆分，逐层量化可分解为行的子问题。其方法演进自 OBQ（Optimal Brain Quantization，arXiv:2208.11580，NeurIPS 2022），后者把 Optimal Brain Surgeon 的二阶剪枝框架迁移到量化，用 Hessian 信息指导误差补偿。

符号说明：WWW 是待量化线性层权重，W^\hat{W}W^ 是量化后的权重，XXX 是由校准样本经过该层得到的输入激活矩阵（列对应样本/token）。目标函数实际是对 W^\hat{W}W^ 求最小值。

对当前仍保持全精度的权重集合 FFF，目标函数的 Hessian 为 HF=2XFXF⊤H_{F}=2X_{F}X_{F}^{\top}HF​=2XF​XF⊤​；FFF 会随着量化进度缩小。工程实现使用阻尼后的 H−1=(2XX⊤+λI)−1H^{-1}=(2XX^{\top}+\lambda I)^{-1}H−1=(2XX⊤+λI)−1，论文默认 λ\lambdaλ 为平均对角线的 1%。补偿公式中的 [:,q][:,q][:,q] 表示取第 qqq 列，和对称 Hessian 下的行写法等价。

OBQ 通过贪心逐个确定误差最小的权重并补偿其余权重来求解；其计算复杂度约为 O(d_row d_col^{3})，在 ResNet-50 级别规模即可接受，但扩展到千亿参数模型不现实。

从 OBQ 到 GPTQ：三个关键改进

为了让二阶 PTQ 方法能够处理千亿参数模型，GPTQ 对 OBQ 做了三项关键改进。

步骤 要解决的问题 算法做法 效果
任意顺序量化 贪心量化顺序对参数化很大的层收益有限 所有列按统一顺序量化；H 只依赖校准输入，权重矩阵各行共用同一个 H 的逆 计算复杂度由 O(d_row d_col^{3}) 降为 O(max(d_row d_col^{2}, d_col^{3}))
惰性批量更新 逐列更新整个矩阵，受显存带宽瓶颈 列块大小 B（论文取 128），块内立即更新、块外暂存；整块处理完一次矩阵乘回写 大模型上提速约一个数量级
Cholesky 重构 反复更新 H 的逆会累积数值误差 加阻尼后做一次 Cholesky 分解，直接取出量化所需行 面向超大模型（论文验证到 175B），并进一步降低数值误差

3.1 固定顺序量化：取消昂贵的贪心搜索

OBQ 倾向于选择当前损失增量最小的权重。GPTQ 论文观察到，对大模型按固定顺序处理列，精度几乎不受影响。因此标准 GPTQ 可从左到右量化输入通道；工程变体也可依据 Hessian 对角线做激活排序（act-order）。

“从左到右量化输入通道”如何理解

对线性层 y=Wxy=Wxy=Wx，假设权重有两个输出通道、三个输入通道：

W=[w11w12w13w21w22w23],x=[x1x2x3]W=\begin{bmatrix}w_{11}&w_{12}&w_{13}\\w_{21}&w_{22}&w_{23}\end{bmatrix},\quad x=\begin{bmatrix}x_1\\x_2\\x_3\end{bmatrix}W=[w11​w21​​w12​w22​​w13​w23​​],x=​x1​x2​x3​​​

将矩阵乘法按列展开：

y=[w11w21]x1+[w12w22]x2+[w13w23]x3y=\begin{bmatrix}w_{11}\\w_{21}\end{bmatrix}x_1+\begin{bmatrix}w_{12}\\w_{22}\end{bmatrix}x_2+\begin{bmatrix}w_{13}\\w_{23}\end{bmatrix}x_3y=[w11​w21​​]x1​+[w12​w22​​]x2​+[w13​w23​​]x3​

因此，W 的第 1、2、3 列分别对应输入通道 x1,x2,x3x_1,x_2,x_3x1​,x2​,x3​。所谓”量化一个输入通道”，实际就是一次处理 W 的一整列，而不是只量化一个矩阵元素。

标准固定顺序可以写成：

W[:,0]→W[:,1]→W[:,2]W[:,0]\rightarrow W[:,1]\rightarrow W[:,2]W[:,0]→W[:,1]→W[:,2]

具体过程是：先量化第一列，用第一列的量化误差调整第二、第三列；再量化已经被调整过的第二列，并用它的误差调整第三列；最后量化第三列。关键在于，后面的列不是直接量化原始值，而是先接收前面列的误差补偿。

是否必须使用原始的左到右顺序

不必须。标准做法可以采用自然列顺序 0,1,2,…,din−10,1,2,\ldots,d_{in}-10,1,2,…,din​−1。启用 act-order 时，先根据 diag⁡(H)\operatorname{diag}(H)diag(H) 对输入通道做一次静态排序。例如排列为 [2,0,1][2,0,1][2,0,1]，算法会先把权重重排成 W[:,[2,0,1]]W[:,[2,0,1]]W[:,[2,0,1]]，再对重排后的矩阵从左到右处理，最后恢复原始顺序。

所以”从左到右”的本质不是要求物理上的原始列号递增，而是：先确定一个固定列顺序，然后沿这个顺序依次量化和补偿，不再像 OBQ 那样每一步动态搜索下一个量化对象。

取消动态贪心选择后，每一行使用完全相同的列顺序，所有输出通道可以并行处理，算法结构也更适合 GPU。

3.2 Lazy Batch Updates：块内立即补偿，块外批量更新

若每量化一列都立刻扫描整个剩余矩阵，计算会受显存带宽限制。GPTQ 把列分成大小为 BBB 的块：

  1. 在当前块内逐列量化。
  2. 每量化一列，立即更新当前块中尚未量化的列，保证后续列看到正确的补偿后权重。
  3. 把每列的归一化误差保存在误差矩阵中。
  4. 当前块完成后，用一次矩阵乘法批量更新块外所有剩余列。

这不改变数学更新，只改变执行顺序，把许多向量级更新合并成高效的 GEMM，并提高缓存局部性。

3.3 Cholesky Reformulation：稳定地使用逆 Hessian 信息

实现先对阻尼后的 Hessian 做 Cholesky 分解，再求逆，最后对逆矩阵再次做上三角 Cholesky：

Hd=H+λI,R=chol⁡(Hd−1)TH_d=H+\lambda I,\quad R=\operatorname{chol}(H_d^{-1})^THd​=H+λI,R=chol(Hd−1​)T

后续代码中的对角项 RiiR_{ii}Rii​ 和行片段 Ri,i:R_{i,i:}Ri,i:​ 直接用于误差归一化及传播。相比在每一步显式做 Sherman–Morrison 式逆矩阵删减，这种重写更适合批处理，也能减少累计数值误差。

3.4 act-order：优先处理高敏感度通道

当启用 actorder 时，按 diag⁡(H)\operatorname{diag}(H)diag(H) 从大到小排列输入通道。直观上，Hessian 对角线较大的通道在校准数据中能量更高，先量化并在自由度最多时进行补偿，通常更稳。完成后必须使用逆置换恢复原始通道顺序。

act-order 不是原始 OBQ 的逐步贪心搜索。 它是在量化开始前根据 Hessian 对角线计算一次静态排列，成本远低于每一步重新评估候选项。

实验结果：把 175B 模型压到 3-4 Bit

实验在 PyTorch 与 HuggingFace（OPT / BLOOM 全系列）上进行，使用单卡 NVIDIA A100（80GB）完成量化；校准数据为 C4 随机抽样 128 段、每段 2048 token，基线为 RTN。模型按 Transformer block 顺序校准：每次只加载一个 block（论文实现中一个 block 含 6 层），累积该 block 各线性层的 Hessian 并执行量化，再把已经量化的 block 重新前向，生成下一 block 的真实输入。因此后续层看到的是”部分量化模型”的输入，而不是整网 FP16 输入。评估 perplexity（WikiText2 / PTB / C4）与 zero-shot 任务（LAMBADA / ARC-Easy / ARC-Challenge / PIQA）。

量化网格采用标准 uniform、per-row、asymmetric、min-max 量化。对每个行或分组，用 scale 和 zero point 把浮点区间映射到 2b2^{b}2b 个整数格点；GPTQ 优化的是在该固定网格上的落点与误差补偿，而不是重新学习网格。group size ggg 表示独立估计 scale / zero point 的连续权重数：论文原始结果以 per-row 为主，g=1024g=1024g=1024 约增加 0.02 bit，g=128g=128g=128 约增加 0.15 bit，但能改善 3-bit 精度；因此名义 bit-width 与 scale / zero point 开销合计后的实际平均 bits-per-weight 需要区分。

实践收益：从多卡推理到单卡生成加速

3 Bit 量化后，OPT-175B 的权重内存约 63GB（embedding 与输出层保留 FP16），另加 2048 token 的 KV cache 约 9GB，可整体放入单张 80GB A100；FP16 需 5 张 A100，8 Bit 的 LLM.int8 需 3 张。

生成延迟（batch=1, seq=128）：A100：FP16 230ms -> 3bit GPTQ 71ms，3.24x 加速；A6000：589ms -> 130ms，4.53x 加速。加速主要来自动态去量化的 kernel（量化矩阵 x FP16 向量），无需激活量化；通信开销小于 5%。

局限与适用边界

  • GPTQ 仅量化权重、不量化激活；在目标场景下激活并非瓶颈，可与 ZeroQuant 等方法组合。
  • 加速来自减少显存读取而非减少计算；主流 GPU 尚不支持 FP16 x INT4 混合精度乘法。
  • kernel 面向小 batch（batch=1）生成场景；大 batch 或计算密集型任务需先反量化再乘。
  • 评测基于 perplexity / zero-shot 准确率；未覆盖偏见等次要指标；C4 校准使部分结果不完全 zero-shot。

核心结论与适用建议

GPTQ 的关键价值不是单纯把权重取整，而是用校准激活构造 Hessian，在每次量化后把误差沿敏感方向补偿到尚未量化的权重；再配合统一量化顺序、128 列惰性批量更新和 Cholesky 重构，才把二阶 PTQ 从小模型算法变成可处理 175B 模型的工程流程。

  • 优先选择 4-bit GPTQ 作为通用部署起点；在显存更紧张且任务容忍少量精度损失时，再评估 3-bit。
  • 需要更高精度时，使用 group size 128 或 act-order，但应同时记录 scale / zero point 带来的额外平均 bits-per-weight。
  • 校准集应覆盖真实输入分布；C4 适合通用语言建模，领域任务最好增加本领域文本并在目标任务上复测。
  • batch=1 的自回归生成最能受益于 GPTQ kernel；大 batch、训练或计算受限的矩阵乘场景，应单独评估反量化和吞吐开销。
  • 本文聚焦论文原始 3-4 Bit 结果；2-bit / ternary 属于极限量化扩展，需要更小 group size 和额外元数据，不应与标准 3-4 Bit 结论混用。
