QuaRot

一句话总结： QuaRot 用随机 Hadamard 矩阵”旋转”LLM 的隐藏状态、FFN 激活和 KV cache，在不改变模型输出的前提下摊平激活中的离群值，使权重、激活、KV cache 全部量化到 4 bit，所有线性层的矩阵乘都在 INT4 上完成，而且不需要为任何离群通道保留高精度。

本文面向做大模型推理优化和模型压缩的同学，默认读者了解 INT4 / INT8 量化与 Transformer 的基本结构。读完可以了解：4-bit 激活量化难在哪；QuaRot 的旋转为什么不改变输出、又为什么能消除离群值；它具体改了模型的哪些地方；效果、代价和适用边界如何。不熟悉正交矩阵、Hadamard 矩阵的话，可以先读 7.1 节的前置知识。除特别标注外，文中数据均来自论文 arXiv v2（2024-10-29）。

论文速览

项目 内容
标题 QuaRot: Outlier-Free 4-Bit Inference in Rotated LLMs

机构 ETH Zurich、EPFL、Microsoft Research、IST Austria & NeuralMagic

链接 论文：arXiv:2404.00456；代码：github.com/spcl/QuaRot（Apache-2.0）

核心结论：

  • 端到端 4 bit： 权重、激活、KV cache 全部 4 bit（W4A4KV4），不保留任何高精度离群通道。Llama 2-70B 的 WikiText-2 困惑度仅从 3.32 升到 3.79，零样本平均准确率保留约 98.6%（论文表述为 99%）。
  • 实测加速： 在 RTX 3090 上，Llama 2-70B 单个 Transformer 块的 prefill 最高加速 3.33×，解码阶段峰值显存节省约 3.9×。
  • 高比特近乎无损： 6 bit / 8 bit 只用最简单的 RTN（round-to-nearest），无需校准数据，困惑度增加不超过 0.09。

要解决的问题：激活中的离群值

LLM 推理分两个阶段。prefill 一次处理整段提示词，主要受算力限制；decode 逐 token 生成，主要瓶颈在显存，长上下文、大 batch 时 KV cache 尤其占显存。

只量化权重（GPTQ、AWQ 等）能压缩模型体积，但计算前仍要把权重反量化回高精度，矩阵乘仍以高精度执行，对算力受限的 prefill 帮助有限。要让矩阵乘真正跑在 INT4 Tensor Core 上，必须同时量化权重和激活；要降低解码显存，还得量化 KV cache。

难点在激活。LLM 的激活中存在离群特征（outlier features）：少数通道的数值远大于其他通道。量化的 scale 由最大值决定，离群值把 scale 撑大，其余绝大多数数值只能挤在少数几个量化级别上。INT4 只有 16 个级别，这个问题比 INT8 突出得多。

已有方案的取舍

方法 量化目标 处理离群值的方式 主要代价
LLM.int8() W8A8 推理时识别离群通道，这部分保留 FP16 计算 混合精度计算，速度不理想

QuaRot W4A4KV4 正交旋转 + 计算不变性，大部分旋转离线融合进权重 每层少量在线 Hadamard 变换

核心思想：旋转不改变输出，却能摊平离群值

Hadamard 旋转如何摊平离群值

Hadamard 矩阵是元素只取 ±1（再乘归一化系数）的正交矩阵。用它乘一个向量，每个输出分量都是所有输入分量的 ±1 加权和：集中在少数通道上的大数值被均匀摊到所有通道，向量长度不变，最大值下降。例如 hidden size 为 4096 时，单个通道上幅值为 M 的离群值，旋转后在每个通道上只贡献 ±M/64。

论文沿用 QuIP 提出的非相干性（incoherence）来刻画这种效果：若 max⁡(W)≤μ∥W∥F/mn\max(W)\le\mu\lVert W\rVert_F/\sqrt{mn}max(W)≤μ∥W∥F​/mn​（mnmnmn 为元素个数），则称矩阵是 μ-非相干的。μ 越大，最大元素相对平均幅度越突出，越难量化；左右乘正交矩阵可以降低 μ。QuaRot 的不同之处在于不仅处理权重，还让激活也变得非相干。

Hadamard 矩阵在工程上还有两个好处。一是快：Walsh-Hadamard 矩阵可以递归构造，H2=12[111−1]H_2=\tfrac{1}{\sqrt{2}}\begin{bmatrix}1 & 1\\ 1 & -1\end{bmatrix}H2​=2​1​[11​1−1​]，H2n=H2⊗H2n−1H_{2^n}=H_2\otimes H_{2^{n-1}}H2n​=H2​⊗H2n−1​，矩阵向量乘只需 O(dlog⁡2d)O(d\log_2 d)O(dlog2​d) 次运算。二是灵活：维度不是 2 的幂时（如 Llama 2-7B 的 FFN 中间维度 11008），把维度拆成 2nm2^n m2nm，再用已知的 m 阶 Hadamard 矩阵做 Kronecker 构造。

这里需要区分两种 Hadamard 矩阵。标准（exact）Hadamard 就是上面递归构造出来的 HHH；随机化 Hadamard 是在它右边乘一个随机对角矩阵，H~=H diag(s)\tilde{H}=H\,\mathrm{diag}(s)H~=Hdiag(s)，其中 sss 的元素从 ±1 中随机取，结果仍然是正交矩阵，这个做法跟随 QuIP#。两者在 QuaRot 中分工不同：只有离线融合进权重的全局矩阵 Q 用随机化 Hadamard，块内的几个变换（down_proj 之前、逐 head 的 value 与 output、RoPE 之后的 query 与 key）用的是标准 Hadamard，论文附录 A.1 写的是 exact Hadamard。论文正文的措辞也留了余地：随机化 Hadamard 只在”方便时”（where convenient）使用。附录 A.5 的消融可以侧面印证这个分工——把 Q 换成随机正交矩阵后，down_proj 和 o_proj 仍然走 Hadamard kernel。论文没有解释为什么这样分工。

计算不变性：把旋转融进权重

如果每次量化前都在线旋转、算完再转回来，开销会很大。QuaRot 借用了 SliceGPT 提出的计算不变性（computational invariance）：在 pre-norm 结构的 Transformer 中，用同一个正交矩阵 QQQ 改写所有相关权重，可以让残差流上的隐藏状态从 XXX 变成 XQXQXQ，而模型输出完全不变。

关键在 RMSNorm。去掉缩放参数后，RMSNorm 只是把每一行除以自身范数，而正交旋转不改变范数，所以二者可以交换顺序：

RMSNorm(X)=RMSNorm(XQ⊤) Q\mathrm{RMSNorm}(X)=\mathrm{RMSNorm}(XQ^{\top})\,QRMSNorm(X)=RMSNorm(XQ⊤)Q

具体分三步：先把 RMSNorm 的缩放参数 α\alphaα 吸收进紧随其后的权重；再让读取残差流的权重（q/k/v_proj、gate/up_proj，以及最后的 LM Head）左乘 Q⊤Q^{\top}Q⊤，例如 Wk←Q⊤diag(α)WkW_k\leftarrow Q^{\top}\mathrm{diag}(\alpha)W_kWk​←Q⊤diag(α)Wk​；最后让写回残差流的权重（Embedding、o_proj、down_proj）右乘 QQQ。相邻层之间的 QQQ 与 Q⊤Q^{\top}Q⊤ 两两抵消。这一步完全离线完成，推理时没有额外开销，而残差流上的激活全部变成了没有离群值的 XQXQXQ，效果如下图。

方法拆解：一个 Transformer 层被改了哪些地方

QuaRot 分两个阶段。阶段一在全精度下改写权重，并在前向中插入少量在线 Hadamard 变换，整个改写不改变模型输出；阶段二对权重做量化，并在前向中加入激活和 KV cache 的在线量化。下图分三部分：(a) 是全局视角，旋转 Q 融合进 Embedding、各层权重和 LM Head；(b) 和 (c) 分别展开 Attention 块和 FFN 块。紫色是离线融合进权重的旋转，蓝色是需要在线计算的 Hadamard 变换，黄色是权重矩阵，虚线框表示融合旋转后量化为 INT4 的权重，竖条是量化点，粉色线表示已被旋转的激活。画法参考了 SpinQuant 论文的 Figure 1。

阶段一：插入旋转，输出保持不变

步骤 作用位置 实现方式 效果
1a 权重改写 残差流，即各模块的输入 全局随机 Hadamard 矩阵 Q 离线融合进所有权重 q/k/v_proj、gate/up_proj 的输入激活无离群值
1b FFN 激活旋转 down_proj 的输入 在线标准 Hadamard 变换，逆变换融合进 down_proj down_proj 的输入可量化
1c Value 旋转 v_proj 输出、o_proj 输入 逐 head 的标准 Hadamard 融合进 v_proj 与 o_proj，跨 head 部分在 o_proj 前在线完成 V cache 与 o_proj 的输入可量化
1d Key 旋转 RoPE 之后的 query 与 key 对 query、key 同时做逐 head 的在线标准 Hadamard 变换 K cache 可量化

Value 为什么能大部分离线处理： 在每个 head 内部，v_proj 与 o_proj 是直接连乘的（PhXWv(h)Wout(h)P_h X W_v^{(h)} W_{out}^{(h)}Ph​XWv(h)​Wout(h)​，PhP_hPh​ 为注意力概率矩阵），因此可以把逐 head 的 Hadamard 矩阵 HdhH_{d_h}Hdh​​ 一正一逆分别融进 WvW_vWv​ 和 WoutW_{out}Wout​。再利用 Hnhdh=(I⊗Hdh)(Hnh⊗I)H_{n_h d_h}=(I\otimes H_{d_h})(H_{n_h}\otimes I)Hnh​dh​​=(I⊗Hdh​​)(Hnh​​⊗I)（论文给出的条件是 head 数与 head 维度均为 2 的幂），只需在 o_proj 前在线补一次跨 head 的 Hnh⊗IH_{n_h}\otimes IHnh​​⊗I，就得到对整段注意力输出的完整 Hadamard 变换。

Key 为什么必须在线处理： RoPE 作用在 q_proj、k_proj 的输出上，旋转无法直接融进这两个权重，所以要在 RoPE 之后对 query 和 key 同时做逐 head 在线旋转；两者的旋转在注意力分数中相互抵消，结果不变。论文选择缓存 RoPE 之后的 key（Post-RoPE caching）：解码时只有 1 个 query，却有大量缓存的 key，这样每步只需旋转 1 个新 token。若改为缓存 RoPE 之前的 key（Pre-RoPE caching），query 虽然不用旋转，但每个 query 都要对缓存的 key 和 value 做在线逆旋转。

论文强调，QuIP# 这类方法在前向中每个权重矩阵需要两次 Hadamard 变换，而 QuaRot 借助计算不变性把大部分旋转融进权重，每个 Transformer 层只需 1½ 次在线 Hadamard 变换。结合方法描述来理解：down_proj 前是一次完整变换，o_proj 前的跨 head 变换只算半次（另一半已融进 v_proj）；query / key 的逐 head 旋转是为量化 KV cache 额外增加的小变换。

阶段二：量化

对象 方法 粒度与设置
权重 默认 GPTQ，也可用 RTN 逐列（per-channel）对称量化；裁剪比例通过线性搜索最小化平方误差；GPTQ 校准集为 128 条 WikiText-2 样本（长度 2048）
激活（线性层输入） 在线 RTN 逐 token 对称量化，scale = 行内最大绝对值 / 7；固定裁剪比例 0.9
KV cache 在线 RTN 非对称量化，group size 128（等于 head 维度）；固定裁剪比例 0.95；query 保持 FP16

实现上，INT4 矩阵乘基于 CUTLASS 在 Tensor Core 上执行，INT32 累加后乘以行（激活）和列（权重）scale，反量化回 FP16；去掉缩放后的 RMSNorm 保持 FP32 计算。KV cache 量化基于 FlashInfer 实现，注意力采用类似 FlashAttention 的在线 softmax：按段读取量化的 KV，反量化后用 FP16 计算。模型改写本身很快，单张 A100 上处理 Llama 2-70B 约 5 分钟，GPTQ 量化另需约 2 小时。

实验结果

主实验在 Llama 2 的 7B / 13B / 70B 上进行。精度看 WikiText-2 困惑度（序列长度 2048，越低越好）和 6 个零样本任务的平均准确率（PIQA、WinoGrande、HellaSwag、LAMBADA、ARC-Easy、ARC-Challenge，使用 LM Evaluation Harness）；性能测试使用消费级 GPU RTX 3090。除特别说明外，QuaRot 均指权重、激活、KV cache 全部 4 bit，权重用 GPTQ 量化。

精度：明显优于同期 4-bit 方案

QuaRot 不保留任何离群通道，也不需要重新训练，困惑度损失最多 0.63（7B），70B 仅 0.47。分组量化设置下，QuaRot-128G 在 7B 上比 Atom-128G 低 0.10，13B 上持平。

消融实验

  • 6 / 8 bit 用 RTN 就够： INT8 困惑度增加不超过 0.03，INT6 不超过 0.09，且 RTN 不需要校准数据。
  • 4 bit 下 GPTQ 优于 RTN，差距随规模缩小： 困惑度（RTN vs GPTQ）7B 为 8.37 vs 6.10，70B 为 4.14 vs 3.79，小模型更需要 GPTQ。
  • Hadamard 优于随机正交矩阵： 换成随机正交矩阵后，7B 困惑度从 6.10 升到 7.45，70B 从 3.79 升到 4.07。
  • 分组量化继续提升精度： 7B 困惑度从 6.10 依次降到 5.98（256G）、5.93（128G）、5.88（64G），代价是要存更多 scale、kernel 更复杂。
  • key 比 value 更敏感： 只量化 KV cache 时，7B 的 K4V4 困惑度为 5.51（基线 5.47），K3V3 为 5.68；K4V2 为 5.75，而 K2V4 升到 8.06。
  • 仅权重量化也受益： Llama 2-70B 的 2-bit 仅权重量化，GPTQ 困惑度为 25.30，加上 QuaRot 后降到 5.60。
  • 在线 Hadamard 精度不敏感： 用 FP16 代替 FP32 计算在线 Hadamard，精度差异可视为噪声（7B 困惑度 6.08 vs 6.10）。

局限与适用边界

  • 性能评测范围有限： 速度和显存数据只覆盖单个 Transformer 块和 RTX 3090，没有端到端整模型的吞吐或延迟；作者也提到 kernel 还有优化空间，例如把量化融合进矩阵乘。
  • 4-bit 精度依赖 GPTQ： 需要校准数据和额外的量化时间；改用免校准的 RTN 时，小模型损失明显（Llama 2-7B 困惑度 8.37）。
  • 新模型更难量化： Llama 3-70B 在 W4A4KV4 下零样本平均准确率下降约 10.7 个百分点，上线前需要在目标模型和任务上验证。
  • 结构前提： 方法基于 pre-norm 结构（每个模块前有 LayerNorm / RMSNorm）；非 2 的幂的维度需要拆成 2nm2^n m2nm，并依赖已知的 m 阶 Hadamard 矩阵。
  • 尚未覆盖： 残差流本身仍保持 FP16；MoE 架构尚未验证。两者都被作者列为后续方向。
  • 小 batch 解码： batch ≤ 8 时 INT4 KV cache 的注意力比 FP16 慢，收益主要体现在大 batch 或长序列。
  • 硬件（本文补充，非论文内容）： INT4 加速依赖 INT4 Tensor Core。论文使用的 RTX 3090（Ampere）支持 INT4，但 H100 等 Hopper GPU 的 Tensor Core 不支持 INT4 矩阵乘（INT4 mma 指令会退化到 CUDA Core 执行，见 arXiv:2402.13499），在这类硬件上拿不到论文中基于 INT4 Tensor Core 的加速，部署前需要确认目标 GPU 的支持情况。

延伸阅读

前置知识：从单位矩阵到 Hadamard 矩阵

四个概念层层递进：归一化后的 Hadamard 矩阵 ⊂ 正交矩阵 ⊃ 旋转矩阵。QuaRot 需要的变换本质上是正交变换，而 Hadamard 矩阵归一化后正好是正交矩阵，同时兼具消除离群值与快速计算两个优势。

单位矩阵（Identity Matrix）

公式中的 III 指单位矩阵——一个 n×nn\times nn×n 方阵，主对角线元素全为 1，其余元素全为 0。它是矩阵乘法里的「1」，任何矩阵乘以它都保持不变，任何向量经它变换也原样不动：AI=IA=AAI = IA = AAI=IA=A，Ix=xIx = xIx=x。可以把 III 理解为恒等变换的矩阵形式。

它有两个关键用法：

  • 正交矩阵 QQ⊤=IQQ^{\top} = IQQ⊤=I：用 QQQ 变换后再用 Q⊤Q^{\top}Q⊤ 变换，两步合起来等于什么都没做，等价于 Q−1=Q⊤Q^{-1}=Q^{\top}Q−1=Q⊤。这正是 (XQ)(Q⊤W)=X(QQ⊤)W=XW(XQ)(Q^{\top}W)=X(QQ^{\top})W=XW(XQ)(Q⊤W)=X(QQ⊤)W=XW 成立、旋转前后模型输出完全不变的根本原因（见 3.2 节）。
  • Hadamard 矩阵 HH⊤=nIHH^{\top} = nIHH⊤=nI：右边是 nnn 倍单位矩阵，说明 HHH 还差一个 1n\tfrac{1}{\sqrt{n}}n​1​ 缩放才是正交矩阵。

正交矩阵（Orthogonal Matrix）

方阵 QQQ 若满足 Q⊤Q=QQ⊤=IQ^{\top}Q = QQ^{\top} = IQ⊤Q=QQ⊤=I（等价于 Q−1=Q⊤Q^{-1} = Q^{\top}Q−1=Q⊤），即为正交矩阵。它的各列（各行）构成一组标准正交基：两两垂直、每个长度为 1。核心性质是保长、保内积：

∥Qx∥=∥x∥,(Qx)⋅(Qy)=x⋅y\lVert Qx\rVert = \lVert x\rVert,\qquad (Qx)\cdot(Qy) = x\cdot y∥Qx∥=∥x∥,(Qx)⋅(Qy)=x⋅y

也就是说，正交变换只是把空间整体转动或翻转，不改变向量的长度和向量之间的夹角，其行列式恒为 ±1\pm 1±1。

旋转矩阵（Rotation Matrix）

旋转矩阵是正交矩阵的子集，额外要求行列式为 +1+1+1，即 Q⊤Q=IQ^{\top}Q = IQ⊤Q=I 且 det⁡(Q)=+1\det(Q) = +1det(Q)=+1。det⁡=+1\det = +1det=+1 是纯旋转，保持朝向不变；det⁡=−1\det = -1det=−1 则含一次反射（镜像翻转）。两者都保长保角，区别只在于是否翻转朝向。二维旋转矩阵最直观：

R(θ)=(cos⁡θ−sin⁡θsin⁡θcos⁡θ)R(\theta)=\begin{pmatrix}\cos\theta & -\sin\theta\\ \sin\theta & \cos\theta\end{pmatrix}R(θ)=(cosθsinθ​−sinθcosθ​)

QuaRot 论文里说的「旋转」其实是广义正交变换，既可以是纯旋转也可以是反射。对量化真正重要的是正交性（保长），而不是严格的 det⁡=+1\det=+1det=+1，所以 Hadamard 矩阵即便对应反射也完全可用。

Hadamard 矩阵（Hadamard Matrix）

元素只取 +1+1+1 或 −1-1−1 的 n×nn\times nn×n 方阵 HHH，若满足 HH⊤=nIHH^{\top} = nIHH⊤=nI，即为 Hadamard 矩阵。注意右边是 nInInI 而不是 III，所以 HHH 本身还不是正交矩阵，归一化之后才是：

Q=1nH  ⟹  QQ⊤=IQ = \tfrac{1}{\sqrt{n}}H \;\Longrightarrow\; QQ^{\top} = IQ=n​1​H⟹QQ⊤=I

构造方式是 Sylvester 递归，阶数为 2 的幂时尤其简单：

H1=(1),H2n=(HnHnHn−Hn)H_1=\begin{pmatrix}1\end{pmatrix},\qquad H_{2n}=\begin{pmatrix}H_n & H_n\\ H_n & -H_n\end{pmatrix}H1​=(1​),H2n​=(Hn​Hn​​Hn​−Hn​​)

例如 H2=(111−1)H_2=\begin{pmatrix}1 & 1\\ 1 & -1\end{pmatrix}H2​=(11​1−1​)。这种递归结构正是快速算法（FWHT）的来源。本文 3.1 节写的 H2=12[111−1]H_2=\tfrac{1}{\sqrt{2}}\begin{bmatrix}1 & 1\\ 1 & -1\end{bmatrix}H2​=2​1​[11​1−1​] 就是归一化之后的形式，两处差的就是这个 1n\tfrac{1}{\sqrt{n}}n​1​ 系数。

为什么 Hadamard 矩阵适合做 QuaRot 的旋转矩阵

QuaRot 对旋转矩阵的几项需求，Hadamard 矩阵恰好全部命中：

需求 Hadamard 矩阵为何满足
计算不变性 归一化后正交，QQ⊤=IQQ^{\top}=IQQ⊤=I，因此 (XQ)(Q⊤W)=X(QQ⊤)W=XW(XQ)(Q^{\top}W)=X(QQ^{\top})W=XW(XQ)(Q⊤W)=X(QQ⊤)W=XW，旋转前后模型输出完全一致
消除离群值（核心） 每个元素幅值相等（±1/n\pm 1/\sqrt{n}±1/n​），变换后每个输出维度都是所有输入维度的均匀 ± 组合，把集中在个别通道的离群值摊平到所有维度
高效计算 递归结构支持 FWHT，复杂度 O(nlog⁡n)O(n\log n)O(nlogn)（类比 FFT），远优于普通矩阵乘的 O(n2)O(n^2)O(n2)；块内的在线 Hadamard 变换正是靠这一点才划算
无需学习、稳定 矩阵固定、与数据无关，不引入额外参数；靠蝶形运算即可完成，无需存储整个矩阵

摊平离群值的机制在 3.1 节已经展开：正交变换保总能量，但会重新分配能量。Hadamard 变换的每一行都是幅值相同的 ± 组合，做一次 HxHxHx 相当于把每个输入分量均匀打散进所有输出分量，原本堆在单一通道的能量被均摊出去，分布趋于均匀、动态范围显著变小，量化误差随之变小。再配合随机符号翻转（随机化 Hadamard＝Hadamard 矩阵 × 随机对角 ±1 矩阵），可以从概率上保证任意输入向量的能量都被近似均匀打散，而不只对特定输入有效——这也是 QuaRot 把融合进权重的全局矩阵 Q 做随机化的原因。
