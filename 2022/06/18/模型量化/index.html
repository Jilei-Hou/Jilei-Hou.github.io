模型量化

简单来说，模型量化（Model Quantization）就是用低比特的定点数（整数）来表示模型中原本的浮点数。比如原来模型的权重（weight）和激活（activation）都是 FP32，量化后都变成 INT8，这种配置通常记作 W8A8，即权重 8 bit、激活 8 bit。

量化的收益主要有两点：

  • 模型更小：FP32 每个数占 4 字节，INT8 只占 1 字节，存储开销降为原来的 1/4。
  • 推理更快、功耗更低：从 32 bit 降到 8 bit 后，矩阵乘的计算代价大约降为原来的 1/16（与位宽成平方关系）[2]，数据位宽变小也减轻了访存带宽的压力。很多端侧 NPU、DSP 主要就是为定点运算设计的。

代价是低比特表示会引入量化误差，可能导致模型精度下降。下面介绍的各种概念和方法，大多是为了在量化之后尽量减少精度损失。

本文先介绍量化的基本概念，再介绍量化方法（PTQ / QAT）和校准方法，文末附常见配置速查表。

均匀量化和非均匀量化（Uniform and Non-Uniform Quantization）

  • 均匀量化：相邻量化值之间的间隔（量化步长）都相等，见上图左侧。均匀量化可以直接用整数乘加实现，硬件和推理框架的支持最好，是目前的主流做法。后文的对称量化和非对称量化都属于均匀量化。
  • 非均匀量化：量化步长不相等，见上图右侧。例如步长按指数增长的对数量化，以及 QLoRA 中按正态分布分位数设计的 NF4 格式。非均匀量化可以在数值密集或对误差敏感的区域使用更小的步长，相同比特数下精度更高；缺点是无法直接用整数乘加计算，通常要查表或依赖专用硬件，部署成本更高。

对称量化和非对称量化（Symmetric and Asymmetric Quantization）

均匀量化本质上是一个线性映射：用缩放因子 scale 把浮点数映射到整数网格上。根据浮点数 0 是否正好映射到整数 0，可以分为对称量化和非对称量化。如上图所示，对称量化的浮点范围关于 0 对称（图中为 [-1, 1]）；非对称量化的范围可以不对称（图中为 [-0.5, 1.5]），需要额外引入一个零点 zero_point，把整数网格整体平移。注意上图来自参考文献 [1]，其中零点的符号约定和本文相反（图中浮点 0 映射到 -Z）。

非对称量化

  • 量化公式

两者对比

对称量化在数据分布不对称时会浪费表示范围。比如浮点数全是正数（如 ReLU 的输出），量化后只会用到 [0, 127]，有符号 INT8 的负半轴 [-128, -1] 完全浪费，相当于只用了 7 bit。非对称量化通过 zero_point 平移整数网格，让 [tmint_{min}tmin​, tmaxt_{max}tmax​] 用满全部 256 个整数值，这类数据的量化精度更高。

非对称量化的额外计算量来自 zero_point。以矩阵乘的一个输出 y=∑i=1Nwixiy = \sum_{i=1}^{N} w_i x_iy=∑i=1N​wi​xi​ 为例，如果权重和激活都用非对称量化：

y≈swsx∑i=1N(wq,i−zw)(xq,i−zx)y \approx s_w s_x \sum_{i=1}^{N} (w_{q,i} - z_w)(x_{q,i} - z_x)y≈sw​sx​i=1∑N​(wq,i​−zw​)(xq,i​−zx​)

=swsx(∑iwq,ixq,i−zx∑iwq,i−zw∑ixq,i+Nzwzx)= s_w s_x \left( \sum_{i} w_{q,i} x_{q,i} - z_x \sum_{i} w_{q,i} - z_w \sum_{i} x_{q,i} + N z_w z_x \right)=sw​sx​(i∑​wq,i​xq,i​−zx​i∑​wq,i​−zw​i∑​xq,i​+Nzw​zx​)

  • 第 1 项是纯整数乘加，和对称量化的计算相同。
  • 第 2、4 项只依赖权重和量化参数，可以离线算好，合入 bias。
  • 第 3 项依赖输入数据，每次推理都要额外计算，这是主要的额外开销。

如果权重用对称量化（zw=0z_w = 0zw​=0），第 3、4 项就都消失了。因此常见的做法是权重用对称量化，激活用非对称量化，参考文献 [2] 推荐的也是这种配置。

计算示例

以 INT8 非对称量化为例。假设某层权重的范围是 [-2.0, 6.0]，用 min-max 方法取阈值，即 tmin=−2.0t_{min} = -2.0tmin​=−2.0，tmax=6.0t_{max} = 6.0tmax​=6.0；INT8 的整数范围是 [-128, 127]，即 qmin=−128q_{min} = -128qmin​=−128，qmax=127q_{max} = 127qmax​=127。s 和 z 的计算过程如下：

s=(6.0−(−2.0))/(127−(−128))=8.0/255≈0.031373s = (6.0 - (-2.0)) / (127 - (-128)) = 8.0 / 255 \approx 0.031373s=(6.0−(−2.0))/(127−(−128))=8.0/255≈0.031373

z=round(127−6.0/s)=round(127−191.25)=round(−64.25)=−64z = \mathrm{round}(127 - 6.0 / s) = \mathrm{round}(127 - 191.25) = \mathrm{round}(-64.25) = -64z=round(127−6.0/s)=round(127−191.25)=round(−64.25)=−64

浮点数 定点数

-2.0 -128

得到 s 和 z 后，就可以求任意浮点数对应的定点数。比如有一个权重 xf=0.28x_f = 0.28xf​=0.28：

量化：xq=round(0.28/s)+(−64)=round(8.925)−64=9−64=−55x_q = \mathrm{round}(0.28 / s) + (-64) = \mathrm{round}(8.925) - 64 = 9 - 64 = -55xq​=round(0.28/s)+(−64)=round(8.925)−64=9−64=−55

反量化：x^f=s⋅(−55−(−64))=9s≈0.2824\hat{x}_f = s \cdot (-55 - (-64)) = 9s \approx 0.2824x^f​=s⋅(−55−(−64))=9s≈0.2824

反量化结果 0.2824 和原值 0.28 相差约 0.0024，这就是舍入带来的量化误差。只要数据落在 [tmint_{min}tmin​, tmaxt_{max}tmax​] 范围内，这个误差最大不超过 s/2≈0.0157s/2 \approx 0.0157s/2≈0.0157。

Power of Two（PoT）量化

PoT 量化是对称量化的一种特殊形式，它把 scale 限制为 2 的整数次幂（k 为整数）：

s=2−ks = 2^{-k}s=2−k

这种方式对硬件友好：乘以或除以 s 都可以用移位（bit shift）完成，不需要做乘法。代价是 scale 的取值受限，在舍入误差和截断误差（见后文“校准方法”）之间更难取得平衡，精度通常不如 scale 可以任意取值的情况。

静态量化和动态量化（Static and Dynamic Quantization）

  • 静态量化：部署前就确定好权重和激活的量化参数（激活的参数用校准数据统计得到），推理时参数固定不变。推理时没有额外开销，但激活的实际范围会随输入变化，如果校准数据不够有代表性，误差会比较大。
  • 动态量化：权重的量化参数仍然离线计算，激活的量化参数在推理时根据当前输入实时计算（例如统计当前输入的最小值和最大值）。它不需要校准数据，能适应不同输入的数据范围，精度通常更好；代价是每次推理都要额外统计激活范围，推理更耗时。大语言模型中常对激活按 token 做动态量化，即后文“量化粒度”中的 Per-Token 量化。

量化粒度（Quantization Granularity）

量化粒度指多少个数共用一组量化参数（s 和 z）。粒度越细，每组参数越贴合这组数据的实际范围，量化误差越小；代价是要存储或实时计算更多的量化参数，硬件实现也更复杂。常见的粒度有以下五种：

  • Per-Tensor（LayerWise，逐层）：整个张量共用一组量化参数，权重和激活都可以用，实现最简单，开销最小。缺点是如果张量内不同部分的数值范围差异很大，范围小的部分只能用到很少的量化值，误差会很大。
  • Per-Channel（ChannelWise，逐通道）：用于权重，每个输出通道一组量化参数。例如形状为 [C_out, C_in, K_h, K_w] 的卷积权重有 C_out 组参数；全连接层权重则是每一行（对应一个输出）一组参数。
  • Per-Group（GroupWise，逐组）：用于权重，把每个输出通道的权重再沿输入维度按固定长度（如 64 或 128 个元素）分组，每组一组参数。常用于大模型的低比特权重量化，例如 GPTQ、AWQ 常用的 W4A16 配置（权重 4 bit，激活保持 FP16），组大小一般取 128。代价是 scale 的存储开销更大：组大小为 128、scale 用 FP16 存储时，平均每个权重要多占 16/128 = 0.125 bit。
  • Per-Token（TokenWise，逐 token）：用于激活，常见于 Transformer 类模型。激活矩阵的形状为 [T, C_in]（T 为 token 数），每个 token（即每一行）一组量化参数。同一个输入里不同 token 的数值范围可能相差很大，Per-Tensor 只能按整个张量的最大值取范围，范围小的 token 精度损失大；Per-Token 让每个 token 按自己的范围量化。因为每次输入的 token 都不同，Per-Token 一般配合动态量化，推理时实时计算每个 token 的 scale，例如 ZeroQuant 和 SmoothQuant（O1 配置）的激活都是这样量化的 [6]。
  • Per-Block（BlockWise，逐块）：权重和激活都可以用。把张量沿矩阵乘的累加维度（输入维度 C_in）每隔固定长度切成一个 block，每个 block 一个 scale。MX 系列格式（MXFP8、MXFP6、MXFP4、MXINT8）和 NVFP4 都采用这种粒度：MX 每 32 个元素一个 block，scale 是 E8M0 格式的 2 的幂；NVFP4 每 16 个元素一个 block，scale 用 FP8 E4M3 表示，再乘上一个张量级的 FP32 scale [8][11]。形式上它和 Per-Group 一样是沿输入维度分组，区别在于用法：Per-Group 一般只用于权重，组较大（64 或 128），scale 用 FP16 存储，计算前要先反量化回 FP16；Per-Block 的 block 更小，scale 本身也是低比特格式，权重和激活都按 block 量化（激活的 scale 在推理时动态计算），硬件直接在低精度矩阵乘中使用这些 scale。之所以要把 block 切得这么小，是因为 FP4 只有 8 个非负可表示值，一个离群值就会让同组的其他数被舍入到 0 附近；block 足够小，离群值的影响就只限于它所在的 16 或 32 个元素。scale 带来的额外存储为：MXFP4 平均每个元素多 8/32 = 0.25 bit，NVFP4 多 8/16 = 0.5 bit。

CNN 部署中最常见的组合是激活用 Per-Tensor，权重用 Per-Channel；大模型的 W8A8 量化中则常用激活 Per-Token，权重 Per-Channel。为什么激活可以按 token 划分，却一般不按通道划分，可以从矩阵乘的计算看出来（以对称量化为例）：

ytj=∑ixtiWji≈sx,t⋅sw,j∑ixq,ti⋅Wq,jiy_{tj} = \sum_{i} x_{ti} W_{ji} \approx s_{x,t} \cdot s_{w,j} \sum_{i} x_{q,ti} \cdot W_{q,ji}ytj​=i∑​xti​Wji​≈sx,t​⋅sw,j​i∑​xq,ti​⋅Wq,ji​

其中 ttt 是 token，jjj 是输出通道，累加沿输入通道 iii 进行。激活的 scale 按 token 划分（sx,ts_{x,t}sx,t​），权重的 scale 按输出通道划分（sw,js_{w,j}sw,j​），两者都和 iii 无关，可以提到求和号外面：先完成纯整数的累加，最后再乘上 scale，几乎不增加计算量。激活用 Per-Tensor 时，相当于所有 token 共用同一个 sx,ts_{x,t}sx,t​。如果激活按输入通道各用一个 scale，sx,is_{x,i}sx,i​ 就没法提到求和号外，整数累加无法直接进行，所以激活一般不做 Per-Channel 量化 [6]。

Per-Block 的 scale 沿输入通道变化，看起来和上面的结论矛盾。实际做法是把累加按 block 拆开：每个 block 内部的 scale 相同，可以先做低精度累加，再乘上这个 block 的 scale，最后把各 block 的结果加起来：

ytj≈∑bsx,t,b⋅sw,j,b∑i∈bxq,ti⋅Wq,jiy_{tj} \approx \sum_{b} s_{x,t,b} \cdot s_{w,j,b} \sum_{i \in b} x_{q,ti} \cdot W_{q,ji}ytj​≈b∑​sx,t,b​⋅sw,j,b​i∈b∑​xq,ti​⋅Wq,ji​

其中 bbb 是输入维度上的 block 编号。每个 block 都要多做一次 scale 乘法，用软件实现开销不小，所以 Per-Block 依赖硬件支持：NVIDIA Blackwell 的 Tensor Core 在矩阵乘指令内部直接处理 MX 和 NVFP4 的 block scale [8]。Per-Block 有时也指二维分块，例如 DeepSeek-V3 的 FP8 训练中，激活按 1×128（每个 token 每 128 个通道）分块，权重按 128×128 分块；由于 Hopper 的 Tensor Core 不支持 block scale，部分和要搬到 CUDA Core 上乘 scale，再用 FP32 累加 [12]。

Per-Token 解决的是不同 token 之间范围差异大的问题。大模型激活中的离群值往往集中在少数几个固定的通道上，Per-Token 处理不了这种情况：OPT-175B 在 INT8 Per-Token 激活量化下，平均精度从 FP16 的 71.6% 降到 31.7%。SmoothQuant 就是针对这个问题提出的 [6]。

量化位宽与数据格式（Bit-width and Data Format）

前文的例子都以 INT8 为主。实际可选的位宽和数据格式还有很多，常见的如下：

格式 组成 表示范围 常见用途
INT8 8 bit 整数 [-128, 127] 硬件支持最广，用于 CNN 和大模型的 W8A8
INT4 4 bit 整数 [-8, 7] 大模型的权重量化（W4A16），一般配合 Per-Group
FP8 E4M3 1 位符号 + 4 位指数 + 3 位尾数 ±448 权重和激活 [7]
FP8 E5M2 1 位符号 + 5 位指数 + 2 位尾数 ±57344 训练中的梯度 [7]
MXFP4 E2M1 元素，每 32 个元素共享一个 2 的幂 scale（E8M0），平均 4.25 bit 元素 ±6 OCP 开放标准，Blackwell 等新硬件原生支持
NVFP4 E2M1 元素，每 16 个元素共享一个 FP8 E4M3 scale，另有一个张量级 FP32 scale，平均约 4.5 bit 元素 ±6 NVIDIA Blackwell 原生支持 [8]

浮点格式本身就是一种非均匀量化。浮点数的可表示值在 0 附近密，绝对值越大越稀。以 FP4（E2M1）为例，可表示的非负值只有 0、0.5、1、1.5、2、3、4、6 这 8 个，相邻间隔从 0.5 增大到 2。和 NF4 不同，FP8、FP4 有硬件直接支持，可以直接做矩阵乘，例如 H100 上 FP8 Tensor Core 的峰值算力是 FP16 的 2 倍 [10]。

浮点格式同样需要 scale。FP8 的表示范围有限，量化时要先用 scale 把数据缩放到表示范围内，再舍入到最近的可表示值。例如 FP8 E4M3 按张量量化时，s=amax/448s = \mathrm{amax}/448s=amax/448（amax 为张量绝对值的最大值），和对称量化的 scale 计算方式一样。MXFP4 和 NVFP4 则把 scale 做到了 Per-Block 粒度（见「量化粒度」一节）：MXFP4 的 scale 只能是 2 的幂，相当于前文的 PoT 量化；NVFP4 的 scale 用 FP8 表示，取值更精细，分组也更小，所以量化误差更小 [8]。

混合精度（Mixed Precision）：同一个模型里，不同的层可以用不同的位宽。对量化敏感的层（例如 CNN 的第一层和最后一层）保留 8 bit 或浮点，其余层用更低的位宽，在精度和压缩率之间取得平衡。哪些层敏感，可以用“校准方法”一节末尾提到的逐层敏感度分析来确定。

量化对象与方案选择（What to Quantize）

模型中可以量化的张量主要有三类：

  • 权重：推理时是常量，可以离线量化，主要节省存储和访存。
  • 激活：随输入变化，需要静态或动态地确定量化参数。只有权重和激活都量化，矩阵乘才能在 INT8、FP8 等低精度计算单元上执行。
  • KV Cache：大模型自回归生成时缓存的 Key 和 Value。上下文越长、batch 越大，KV Cache 占的显存越多，甚至会超过权重本身，量化它可以支持更长的上下文和更大的 batch。推理框架中 FP8、INT8 的 KV Cache 较常用；量化到 2 bit 等更低比特时，Key 适合 Per-Channel，Value 适合 Per-Token [9]。KV Cache 量化主要是为了省显存，参与计算前会先反量化，所以不受前文“激活一般不做 Per-Channel”的限制。

按量化哪些张量，大模型中常见的方案分为两类：

  • Weight-only 量化（如 W4A16、W8A16）：只量化权重。计算前先把权重反量化回 FP16，再用 FP16 做矩阵乘，所以它减少的是权重的存储和读取量，计算量不变。
  • 权重激活量化（如 W8A8、FP8）：权重和激活都量化，矩阵乘直接用低精度计算单元执行，访存量和计算时间都会减少。

选哪种方案，要看推理的瓶颈在访存还是计算。以 H100 SXM 为例，FP16 Tensor Core 的稠密峰值算力约 989 TFLOPS，显存带宽 3.35 TB/s，两者之比约为 295 FLOP/Byte [10]。矩阵乘每从显存读入一个 FP16 权重（2 字节），要和 b 个 token 各做一次乘加，即 2b 次运算，所以算术强度约为 b FLOP/Byte（b 为同时计算的 token 数）：

  • decode 阶段：每个请求每次只生成一个 token，b 就是 batch size。batch 较小时 b 远小于 295，瓶颈在显存带宽，加速主要来自权重读取量的减少：W4A16 降到约 1/4，W8A8 降到 1/2，所以 W4A16 通常更快，W8A8 的低精度算力在这里发挥不出来。
  • prefill 阶段和大 batch 服务：一次要处理成百上千个 token，瓶颈在计算。Weight-only 量化基本没有加速效果，反量化还有额外开销，这时需要 W8A8 或 FP8 才能用上低精度计算单元。

这也是开头“矩阵乘的计算代价降为 1/16”的前提：实际能加速多少，取决于瓶颈在哪里，以及硬件有没有对应位宽的计算单元。

量化感知训练和训练后量化（QAT and PTQ）

按是否需要重新训练，量化方法分为两类，流程对比见上图：

  • 训练后量化（Post-Training Quantization，PTQ）：直接量化训练好的模型，只需要少量校准数据来确定量化参数，不需要训练。流程简单、耗时短，但有精度风险，比特数越低风险越大。
  • 量化感知训练（Quantization-Aware Training，QAT）：在训练（通常是微调）时插入伪量化节点，让前向计算带上量化误差，再通过反向传播调整权重来适应这种误差，精度更有保障；代价是需要训练数据、完整的训练流程和更多算力。

按参考文献 [2] 的结论，大多数情况下 PTQ 就能做到接近浮点精度的 8 bit 量化；QAT 则可以在更低的比特数下取得有竞争力的精度。

QAT 要解决的一个问题是：round 函数的梯度几乎处处为 0，梯度无法直接反向传播。常用的做法是直通估计器（Straight-Through Estimator，STE），即在反向传播时把 round 的梯度近似为 1，梯度原样传回；被 clamp 截断的值梯度为 0。

按易用性还可以进一步把量化方法分为 4 个级别。从 L1 到 L4，使用复杂度逐渐增加，量化精度也更有保障：

  • L1：不需要任何数据（Data-Free），只根据模型权重做量化，例如 DFQ。
  • L2：需要少量数据，不需要 label，用校准（Calibration）的方法计算量化参数，即常规的 PTQ。
  • L3：需要少量数据，通过梯度下降优化权重的取整方式或量化参数，例如 AdaRound、BRECQ。这类方法通常以逐层或逐块的输出重建误差为优化目标，一般不需要 label。
  • L4：需要全量数据和 label，以及完整的训练 pipeline，即 QAT。

QAT 实践技巧（Tips for QAT）

  1. 用 PTQ 的结果初始化 QAT：先校准，把 PTQ 得到的量化参数作为 QAT 的起点，最终精度通常比从默认参数开始训练更好。
  2. 用较小的学习率，训练较短的时间：因为原始模型已经收敛，QAT 只需要让模型适应量化误差。参考文献 [4] 的经验值是：微调约为原始训练 10% 的步数，初始学习率取原始训练初始学习率的 1%，并用余弦退火逐渐降低学习率。
  3. 处理好 BN：部署时 BN 一般会折叠进前面的卷积层，QAT 时也应先折叠 BN（或模拟折叠后的权重）再做伪量化，保证训练时量化的权重和部署时一致。训练后期可以冻结 BN 统计量和量化参数，只微调权重。

模拟量化和全整型量化（Simulated and Integer-only Quantization）

  • 模拟量化（又称伪量化，Fake Quantization）：在浮点模型中插入伪量化节点，对张量先量化再反量化，引入和真实量化相同的误差，但模型中的算子仍然用浮点计算。它主要用于在训练框架中评估量化后的精度，QAT 训练的也是这种模型。
  • 全整型量化：乘加等运算真正用整数执行，是最终部署到硬件上的形式。以卷积和全连接为例，INT8 和 INT8 的乘积在 INT32 中累加，累加结果再乘以系数 M=swsx/syM = s_w s_x / s_yM=sw​sx​/sy​，重新量化（requantize）为 INT8 作为下一层的输入，其中 sys_ysy​ 是输出的 scale。为了避免浮点乘法，MMM 通常表示为定点乘法加移位的形式 M=M0⋅2−nM = M_0 \cdot 2^{-n}M=M0​⋅2−n，M0M_0M0​ 用定点整数表示，nnn 是移位的位数 [3]。

QAT 和 PTQ 一般都是先生成伪量化模型，再由推理框架或编译器转换成全整型模型。这一步转换也会带来一定的精度损失，尤其是 Softmax、LayerNorm、GELU 等非线性算子，用整数近似实现时精度损失的风险更大，部署时这类算子常保持浮点计算。

校准方法（Calibration）

由前文的公式可知，计算 scale 和 zero_point 之前，需要先确定浮点数据的截断阈值 tmint_{min}tmin​ 和 tmaxt_{max}tmax​。权重在推理时是常量，可以直接统计；激活值随输入变化，需要用一批有代表性的样本（校准集）跑一遍模型来统计，这个过程叫做数据校准（Calibration）。校准集一般几百个样本就够了，TensorRT 文档给出的经验值是：约 500 张图片足以校准 ImageNet 分类模型 [5]。

选择阈值时，需要在两种误差之间权衡：

  • 截断误差（clipping error）：超出阈值的值被 clamp 到边界上产生的误差。阈值范围越小，截断误差越大。
  • 舍入误差（rounding error）：范围内的值四舍五入到最近的量化值产生的误差，最大为 s/2。阈值范围越大，s 越大，舍入误差也越大。

常用的校准方法如下，其中 Max、Entropy、Percentile 在各深度学习框架中用得最多：

  • Max：取数据绝对值的最大值作为阈值（非对称量化则分别取最小值和最大值）。不会产生截断误差，但当数据中有离群点（outlier）时，范围会被拉得很大，大部分正常数值的舍入误差都会变大。TensorRT 文档提到，这种方法在 NLP 任务上的效果更好 [5]。
  • Entropy：在一系列候选阈值中，选出使量化后分布与原始分布之间 KL 散度最小的那个，通常会截掉一部分长尾上的离群值。TensorRT 的 IInt8EntropyCalibrator2 用的就是这种方法，官方建议用于 CNN 类模型 [5]。
  • Percentile：取数据分布中第 k 个百分位数的值作为阈值，例如 99.99% 或 99.999%，直接舍弃最极端的一小部分值。实现简单，但 k 需要按模型调整，取得太小会截断过多，精度明显下降 [4]。
  • MSE：选出使量化前后数据均方误差最小的阈值，直接在截断误差和舍入误差之间求平衡。参考文献 [2] 推荐权重和大部分层的激活都用这种方法。

没有一种校准方法对所有模型都是最好的 [4]，实践中可以多试几种，按量化后的模型精度来选。如果都达不到要求，可以先做逐层的敏感度分析，把最敏感的少数几层保留为浮点（部分量化），仍然不行再考虑 QAT。

CNN INT8 INT8，对称，Per-Channel INT8，Per-Tensor，静态；对称或非对称视硬件而定 PTQ，用 Entropy、Percentile 或 MSE 校准；掉点明显再用 QAT 端侧 NPU、TensorRT 等 INT8 推理
