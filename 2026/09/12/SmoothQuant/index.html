SmoothQuant

背景

SmoothQuant的核心目标是实现 LLMs 的 8 位权重 + 8 位激活值（W8A8）量化。其设计依据是 “模型权重易量化、激活值难量化” ，通过一种数学上等价的转换，在离线状态下把激活值的量化难度转移到权重上，从而消除激活值中的异常值，让量化过程更顺畅。

作者观察发现LLM中featuremap的极值存在于特定维度的channel中，这些outlier值使得量化困难。

核心思想：难度迁移

既然逐通道（per-channel）量化激活能恢复精度、却无法对接 INT8 GEMM 内核（缩放只能在矩阵乘的外维度做），SmoothQuant 换了个思路：不去per-channel量化激活，而是把激活的量化难度「搬」到权重上。

关键观察：激活虽因离群值难量化，但不同 token 在各通道上的变化模式是相似的——离群值固定在特定通道。于是可以对这些通道整体「削峰」，把幅度差异转移给本就平坦、好量化的权重。

具体做法：对激活的指定通道乘上一个小于 1 的缩放因子把峰值压下去，同时对应的权重通道乘上该因子的倒数，使线性层的计算结果数学上完全等价。变换后：

  • 激活 X^\hat{X}X^：离群值被「抹平」，量化范围变紧，有效比特数提升。
  • 权重 W^\hat{W}W^：虽然略微变难，但因原本足够平坦，仍在易量化范围内。

工程友好点：激活通常由前一层（线性层、LayerNorm 等）产生，因此平滑因子可以离线融合进前一层的参数，运行时不引入任何额外的缩放算子，零额外开销。

数学原理

对一个线性层 Y=X⋅WY = X \cdot WY=X⋅W，SmoothQuant 引入逐通道平滑因子 s∈RCis \in \mathbb{R}^{C_i}s∈RCi​，做如下数学等价变换：

Y=(X⋅diag(s)−1)⋅(diag(s)⋅W)=X^W^Y = (X \cdot \mathrm{diag}(s)^{-1}) \cdot (\mathrm{diag}(s) \cdot W) = \hat{X}\hat{W}Y=(X⋅diag(s)−1)⋅(diag(s)⋅W)=X^W^

即激活除以 sss、权重乘以 sss，乘积不变。关键在于如何选 sss：

  • 若令 sj=max⁡(∣Xj∣)s_j = \max(|X_j|)sj​=max(∣Xj​∣)，把全部难度推给权重 → 权重量化误差过大。
  • 若令 sj=1/max⁡(∣Wj∣)s_j = 1/\max(|W_j|)sj​=1/max(∣Wj​∣)，把全部难度推给激活 → 退回原问题。

因此引入迁移强度（migration strength） α\alphaα，在激活与权重之间平衡难度：

sj=max⁡(∣Xj∣)αmax⁡(∣Wj∣)1−α,j=1,2,…,Cis_j = \frac{\max(|X_j|)^{\alpha}}{\max(|W_j|)^{1-\alpha}}, \quad j = 1, 2, \ldots, C_isj​=max(∣Wj​∣)1−αmax(∣Xj​∣)α​,j=1,2,…,Ci​

参数 含义与取值
α\alphaα 迁移强度超参。α\alphaα 越大，越多难度从激活迁移到权重，激活离群值被压制得越狠。
默认 0.5 对大多数模型（OPT、BLOOM 全系列）是平衡点，使权重与激活在对应通道共享相近的最大值、分担量化难度。
0.75 对离群值更严重的模型（如 GLM-130B 约 30% 离群通道），调大 α\alphaα 把更多难度迁往权重。

sss 用预训练数据的校准样本离线估计。在 Transformer 中，默认对 self-attention 和 FFN 的输入激活做平滑、所有线性层走 W8A8，attention 里的 BMM 也走 INT8；而 Softmax、LayerNorm、ReLU 等轻量逐元素算子保持 FP16，以平衡精度与效率。

ModelOpt 中的 SmoothQuant 实现

💡 本章面向源码： 梳理 TensorRT-Model-Optimizer（PyTorch 路径，ModelOpt 中没有对 ONNX 实现的 SmoothQuant）中 SmoothQuant 的调用链路、算法本体与支持算子。核心代码集中在三个文件。

文件 角色
quantization/model_calib.py（smoothquant()） 算法本体：收集统计、计算平滑因子、折叠进权重
quantization/config.py（SmoothQuantCalibConfig） 配置类，定义 alpha 超参
quantization/mode.py（SmoothQuantModeDescriptor） 把算法名 smoothquant 注册为一个 calibrate mode

调用链路

算法本体三步走

对每个满足条件的量化线性层，smoothquant() 执行三步：

第一步：per-channel 收集激活统计

先把 input_quantizer.axis 设为 -1（按输入通道），跑校准数据 max_calibrate，得到每个输入通道的激活幅度 act_amaxact\_amaxact_amax。

第二步：计算平滑因子

scale_a=max⁡(∣W∣)1−α/max⁡(∣X∣)αscale\_a = \max(|W|)^{1-\alpha} / \max(|X|)^{\alpha}scale_a=max(∣W∣)1−α/max(∣X∣)α

随后把激活量化器切回 per-tensor（axis=None），原 per-channel amax 存入 _amax_for_smoothing 备用。

第三步：落地——施加并折叠

激活侧设 pre_quant_scale = scale_a；权重侧 weight *= 1/scale_a 直接折叠进 weight.data，再重算权重 amax。

❗ 注意符号方向： 论文的平滑因子 sj=max⁡(∣Xj∣)α/max⁡(∣Wj∣)1−αs_j = \max(|X_j|)^{\alpha}/\max(|W_j|)^{1-\alpha}sj​=max(∣Xj​∣)α/max(∣Wj​∣)1−α 是「激活除以 sss、权重乘以 sss」。ModelOpt 计算的 scale_ascale\_ascale_a 是论文 sss 的倒数，作为 pre_quant_scale 乘到激活（等价于除以 sss），权重再乘 scale_ascale\_ascale_a 的倒数——数学上与论文完全一致。

工程细节上还做了：张量并行同步（column-parallel 层对 act_amaxact\_amaxact_amax、weight_scaleweight\_scaleweight_scale 做 all-reduce MAX，保证 TP 组内 pre_quant_scale 一致）、零通道保护（amax 接近 0 的通道把 scale 置 1）、以及数值钳制 scale_a∈[10−4,104]scale\_a \in [10^{-4}, 10^{4}]scale_a∈[10−4,104]，防止溢出。

支持的算子

SmoothQuant 遍历模型时，唯一的筛选条件是 is_quantized_linear(module)。该判定的核心要求是：模块是量化模块、含 input_quantizer / weight_quantizer，且权重必须是 2D（GEMM / Linear 类算子）。

✅ 支持：所有 2D 权重的 Linear / GEMM 类模块

  • PyTorch 原生 nn.Linear
  • Megatron：Column / RowParallelLinear（含 TE 版本）
  • Transformer Engine：te.Linear、GroupedLinear、LayerNormLinear
  • vLLM：Row / Column / QKVParallelLinear
  • HuggingFace：HFColumn/RowParallelLinear、FalconLinear、FP8Linear 等
  • apex / fairscale / peft（LoraLinear）/ PyG Linear

❌ 不支持（校准时跳过）

  • nn.Embedding——代码硬编码排除（虽是 2D 权重但非 GEMM）。
  • 所有 Conv / ConvTranspose（1d/2d/3d）——它们能被量化，但权重为 3D/4D/5D，weight.dim()==2 不成立，SmoothQuant 直接跳过、不做平滑。

此外，即便是 Linear，运行期还有三道 warn-and-skip 关卡：必须已校准、仅 INT8（input/weight num_bits 均为 8）、且为 per-channel（axis=-1）且通道数 > 1，否则该层被跳过。

💡 与其他实现区分： 某些内部 ONNX 路径的 SmoothQuant 实现支持 Linear / Conv / ConvTranspose / Gemm，并专门处理 group conv。但本仓库的 PyTorch 实现仅支持 2D 权重的 Linear / GEMM 类算子，不含任何 Conv，两者算子范围不同，不可混用。

配置与预设

配置类 SmoothQuantCalibConfig 只有一个超参 alpha：

项 说明
method 固定 "smoothquant"
alpha 迁移强度，范围 [0, 1]；ModelOpt 默认 1.0（注意：不同于论文常用的 0.5）。α=1.0\alpha=1.0α=1.0 时 scale_a=1/act_amaxscale\_a = 1/act\_amaxscale_a=1/act_amax，把全部难度迁往权重。

开箱预设 INT8_SMOOTHQUANT_CFG（configs/ptq/presets/model/int8_smoothquant.yaml）：权重 per-channel INT8（axis=0）+ 激活 per-tensor INT8——正是 SmoothQuant 的目标形态，平滑因子让 per-tensor 激活也能精确量化。
