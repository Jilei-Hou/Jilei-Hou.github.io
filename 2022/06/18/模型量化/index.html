模型量化

模型量化

简单来说，模型量化（Model Quantization）就是通过某种方法将浮点模型转为定点模型。比如说原来的模型里面的权重（weight）都是float32，通过模型量化，将模型变成权重（weight）都是int8的定点模型。

为什么需要模型量化

随着深度学习（Deep Learning）的发现，其在计算机视觉（Computer Vision， CV）和自然语言处理（Natural Language Processing，NLP）等领域都取得了巨大的成功。通过深度学习，我们可以得到用于处理各种任务的高性能模型，这些模型大多都很复杂、一般只适合在GPU上进行推理，并不适合在板端进行推理，然而在实际应用时，很多场景都需要将模型部署到板端。

为了解决模型难以部署到板端的问题，我们就需要通过模型量化来降低模型的复杂性，这个过程不可避免的会发生精度损失。

量化前的浮点模型和量化后的定点模型的特点：

量化前的浮点模型 量化后的定点模型
参数量大（float32） 压缩参数（int8）
计算量大 提升速度
内存占用多 内存占用少
精度高 精度损失

怎么进行模型量化

模型量化就是建立一种浮点数据和定点数据间的映射关系，使得以较小的精度损失代价获得了较大的收益，要弄懂模型量化的原理就是要弄懂这种数据映射关系。

非对称量化与对称量化

非对称量化

  1. 浮点与定点互转

xq=clamp(round(xf/s)+z,qmin,qmax)x_q = clamp(round(x_f/s)+z, q_{min}, q_{max})xq​=clamp(round(xf​/s)+z,qmin​,qmax​)

xf=s∗(xq−z)x_f = s*(x_q-z)xf​=s∗(xq​−z)

其中，x_q表示量化后的定点数，x_f表示原始的浮点数，s表示scale，z表示zero_point，q_min表示量化bit下的最小值，q_max表示量化bit下的最大值

  1. scale的计算公式

s=(tmax−tmin)/(qmax−qmin)s = (t_{max}-t_{min})/(q_{max}-q_{min})s=(tmax​−tmin​)/(qmax​−qmin​)

其中t_max表示阈值最大值，t_mix表示阈值的最小值。阈值用来表示x_f中待量化的数的上下界，其选取有多种方式，如min-max，kl等

  1. zero_point的计算公式

z=qmax−tmax/sz = q_{max} - t_{max}/sz=qmax​−tmax​/s

示例

从上述的映射关系中，如果知道了阈值，那么其对应的线性映射参数也就知道了，整个量化过程也就明确了。

那么该如何确定阈值呢？

一般来说，对于权重的量化，由于权重的数据分布是静态的，一般直接找出 MIN 和 MAX 线性映射即可；而对于推理激活值来说，其数据分布是动态的，为了得到激活值的数据分布，往往需要一个所谓校准集的东西来进行抽样分布，有了抽样分布后再通过一些量化算法进行量化阈值的选取。

举例：

模型训练后权重或激活值往往在一个有限的范围内分布，如权重值范围为[-2.0, 6.0]，我们选用min-max方法，即t_max = 6.0，t_min = -2.0。然后我们用int8进行模型量化，则定点量化值范围为[-128, 127]，即q_max = 127，q_min = -128，那么s和z的求值过程如下：

s = 6.0 - (-2.0) / (127 - (-128)) = 8.0 / 255 ≈ 0.03137255

z = 127 - 6.0 / 0.03137255 ≈ 127 - 191.25 ≈ -64.25 ≈ -64

可以得到如下对应关系：

浮点数 定点数
6.0 -128
0 -64
-2.0 127

得到量化参数S和Z后，我们就可以求任意一个浮点数对应的定点数，比如说有一个权重等于0.28，即R=0.28

q = 0.28 / 0.03137255 + (-64) ≈ -55

对称量化（一种特殊的非对称量化，zero_point=0）

  1. 浮点与定点互转

xq=clamp(round(xf/s),qmin,qmax)x_q = clamp(round(x_f/s), q_{min}, q_{max})xq​=clamp(round(xf​/s),qmin​,qmax​)

xf=s∗xqx_f = s*x_qxf​=s∗xq​

其中，x_q表示量化后的定点数，x_f表示原始的浮点数，s表示scale，q_min表示量化bit下的最小值，q_max表示量化bit下的最大值

  1. scale的计算公式

s=t/qmaxs = t/q_{max}s=t/qmax​

其中t表示阈值

对称量化中浮点0对应的值就是定点0。对称量化对于正负数不均匀分布的情况不够友好，比如如果浮点数全部是正数，量化后的数据范围是[0, 127], [-128, 0]的范围就浪费了，减弱了int8数据的表示范围

对称量化 vs 非对称量化（一般激活非对称量化，权重对称量化）

为什么激活用非对称：ReLU 后分布只在正半轴

ReLU 输出恒 ≥ 0。设某层 ReLU 后激活实际范围是 [0, 6]。若强行对称量化，范围要撑成 [-6, +6]，256 个 INT8 格点里约一半落在根本没有数据的负半轴，被白白浪费；非对称量化则把范围就设为 [0, 6]，全部格点都铺在有数据的区间上——同样 INT8，分辨率翻倍、量化误差约减半。

对比项 对称 [-6,6] 非对称 [0,6]
有效格点数 约 128 256
量化步长 delta ≈ 0.047 ≈ 0.023
量化误差 大 约为对称的一半

不止 ReLU：GELU、Swish、Sigmoid 等激活输出同样不关于 0 对称，所以非对称对激活的收益是普遍的。而权重分布通常近似关于 0 对称、本就铺满正负两侧，用对称量化不浪费格点。

硬件代价：为什么权重对称、激活非对称

非对称引入非零 zero point，会打破整数 MAC 的简洁性。

硬件真正想要的是 ①（纯整数乘加），②③④ 都是 zero point 带来的额外修正。关键在于这几项代价天差地别：

项 能否离线预计算 运行时代价
① 主 MAC — 必做
② z_x·Σq_w 能：权重和是常数，可折进 bias 几乎为零
③ z_w·Σq_x 不能：激活和依赖每次输入 昂贵
④ N·z_w·z_x 能：常数 零

决定性的是 ③：它需要运行时对每个输出累加输入激活之和 Σq_x，是一份随输入变化的额外开销。于是：激活非对称 + 权重对称（z_w=0）时 ③ 直接消失、只剩可离线折进 bias 的 ②，激活的非对称几乎免费；反之权重非对称会让 ③ 出现，每次推理都要算激活和并修正，代价高、得不偿失。

推荐（也是 AIMET 默认）：权重对称（令 z_w=0，消掉最贵的 ③ 项，兼顾硬件友好）+ 激活非对称（换取分辨率，代价可离线吸收）。这套组合正是「权重分布近似对称、激活分布偏一侧」两种特性的最优匹配。现代 NPU/DSP（如高通 Hexagon HTP）内建了零点处理与重量化通路；也正因权重非对称代价高，很多定点后端硬性要求权重对称，AIMET 的 backend-aware 配置会据目标硬件自动锁定。

为什么用反量化公式展开，而不是量化公式

上面的 MAC 展开代入的是反量化式 w ≈ s_w·(q_w − z_w)（整数 → 浮点），而非量化式 q = clamp(round(w/s) + z, ...)（浮点 → 整数）。原因是：硬件的乘加是在「已经量化好的整数」上做的，要分析它的代价，必须把整数操作数还原成真实数值——这只能沿反量化方向展开。

推理时流进 MAC 单元的操作数是整数 q_w、q_x，硬件高效执行整数累加 Σ q_wᵢq_xᵢ；而我们关心的是它对应的真实点积 Σ wᵢxᵢ。把每个整数操作数反量化回浮点、代入相乘展开，才得到那四项——所以四项本质是「整数累加 ↔ 真实点积」的换算，量化公式（浮点转整数）在这个环节根本没发生。

量化公式对应的是另一个、更早的环节，而且它区分不出对称与非对称的复杂度差异：

环节 谁做 代价 对称 vs 非对称差异
权重量化 离线（转换时一次） 运行时为零 无关
激活量化 / 层间重量化 运行时，逐元素 O(N) 小 仅多一个 +z 加法
MAC 累加 运行时，O(N·K) 主体 大 ③ 项 Σq_x，昂贵

说明：量化是逐元素 O(N)、MAC 是 O(N·K)，分析硬件复杂度要盯住主体开销（MAC）。量化步骤里非对称只是多一个 +z 逐元素加法，对称非对称都便宜、拉不开差距；真正昂贵的 ③ 项（z_w·Σq_x）恰恰是从反量化展开里冒出来的交叉修正项——需要运行时额外累加激活和 Σq_x，既不属于量化公式、也无法用量化公式暴露。

注意：量化公式确实在「层间重量化（requantize）」时重新登场——int32 累加器结果转回下一层 int8 时会先反量化再量化。但那同样是逐元素 O(N)、有专用硬件单元、对称非对称只差一个 +z，因此不改变「权重对称、激活非对称」的结论。

量化粒度

量化粒度 说明
pertensor 对整个张量取一个阈值
perchannel 每个channel得到一个阈值
pertoken 每个token得到一个阈值，一般适用于大模型量化
perblock 按照block进行划分，每个block内得到一个阈值，一般适用于mxint8/nvfp4等数据类型

pertensor

说明：abs(value).max() 在全张量上求标量最大值，再用 np.array([...]) 包成长度为 1 的数组（与 per-channel / per-block 返回向量保持接口一致）。clip 到 [float32.tiny, float32.max] 防止阈值为 0（导致 scale=0 除零）或溢出。最后置 granularity="per-tensor"。

perchannel

注意： 通道轴的选择因算子而异。Conv 权重布局为 [O, I, H, W]，输出通道天然在第 0 维，直接 axis=0；ConvTranspose 权重布局为 [I, O/group, H, W]，需先 reshape 拆出 group 维、再 swapaxes 把输出通道搬到第 0 维，才能复用同一套 per-channel 逻辑。

逐行拆解 ：

  • abs(value)：先取绝对值，量化阈值只关心幅度。
  • .max(tuple(_ for _ in range(value.ndim) if _ != axis))：对除 axis 外的所有维度一次性求 max，结果是一维向量，长度等于第 axis 维（即输出通道数）。这一句不写死维度，所以 4D 的 Conv 权重和经过变换后的 ConvTranspose 权重都能复用。
  • .clip(float32.tiny, float32.max)：下限 tiny 防止某通道全 0 导致阈值为 0（后续 scale 除零）；上限 max 防溢出。
  • max_percentile *：权重默认 max_percentile=1.0（直接取最大），保留接口以便统一缩放。

perblock

关键三步：

  1. 折叠：把任意维张量按目标 axis 折成 [pre_size, axis_size, post_size] 三维，使分块逻辑与原始维数解耦。
  2. 补零对齐：当 axis_size 不是 block_size 整数倍时，在右侧 pad 补零（补零不会抬高 max，安全）。
  3. 切块求 max：reshape 成 [pre, num_blocks, block_size, post]，对 block_size 所在维（axis=2）求 max，flatten() 展平成一维阈值向量。

阈值数量 = pre_size × num_blocks × post_size，其中 num_blocks = ceil(axis_size / block_size)。

校准方法

从上面对两种量化算法的介绍我们不难发现，为了计算 scale 和 zero_point 我们需要知道 FP32 weight/activiation 的实际动态范围。对于推理过程来说， weights 是一个常量张量，不需要额外数据集进行采样即可确定实际的动态范围。但是 activation 的实际动态范围则必须经过采样获取(一般把这个过程称为数据校准(calibration) )。

方法 是否截断 处理离群点方式 适用场景
原始 MinMax ❌无截断 全局极值，单点离群直接废掉 scale 分布稳定无异常值
移动 MinMax（滑动窗口 / EMA） ❌无截断 极值只保留近期信息，抑制偶然瞬时离群 流式、逐 batch 校准；不想做直方图、不想 KL 的开销；离群只是偶尔出现，不是持续存在
Percentile ✅截断 固定百分比 clip 可控切掉固定比例大值
KL 散度 ✅自动截断 最小化分布散度，直方图优化 追求精度，接受直方图开销

minmax

最简单也最直接的量化方法，直接使用tensor中的最大值来表示t_max，最小值来表示t_mix

这种方式一个最大的问题时，当tensor中99%的数值都在[-100, 100]之间，有一个值为10000，那么最终选出来的t为[-100， 10000]，这会导致量化精度明显下降

移动平均minmax

定位：属于改进版 MinMax 校准，用来解决原始 MinMax 被瞬时大离群点污染 scale 的问题；在 PTQ 量化里用于流式校准（逐 batch 收集激活，不是一次性拿到全部校准数据）。

原始 MinMax 的痛点

原始 MinMax：在校准集所有样本上，记录全局 max,minmax, minmax,min。 只要某一个 batch 出现一个超大激活，全局 max 直接被撑大，后续所有层量化 scale 变差。

移动窗口 MinMax：维护一个滑动窗口，只保留最近 N 个 batch 的激活极值；窗口内计算 max,minmax, minmax,min，窗口外的旧极值被丢弃。

两种常见实现版本

版本 1：滑动窗口（Sliding Window）

窗口大小 WWW，保存最近 WWW 个 batch 的 batch_max,batch_minbatch\_max, batch\_minbatch_max,batch_min

  1. 每推理一个校准 batch，计算当前 batch 的激活 (bmax,bmin)(b_{max}, b_{min})(bmax​,bmin​)
  2. 将 (bmax,bmin)(b_{max}, b_{min})(bmax​,bmin​) 加入窗口队列；队列满则弹出最老的一组极值
  3. 当前用于量化的全局极值：

win_max=max⁡(窗口内所有 bmax)win_min=min⁡(窗口内所有 bmin)\begin{aligned} win\_max &= \max(\text{窗口内所有} \ b_{max}) \\ win\_min &= \min(\text{窗口内所有} \ b_{min}) \end{aligned}win_maxwin_min​=max(窗口内所有 bmax​)=min(窗口内所有 bmin​)​

  1. 用 win_max,win_minwin\_max, win\_minwin_max,win_min 计算 scale /zero_point

特点：严格滑动，FIFO；只看最近 W 个 batch，瞬时单点离群点只会短暂影响窗口，不会永久污染。

版本 2：指数移动极值（EMA MinMax，指数平滑最大 / 最小，更常用在流式 PTQ）

不是固定窗口，用指数衰减，给新 batch 更高权重，旧极值权重指数衰减。 很多推理框架里叫 moving_max /moving_min，本质是 EMA 形式：

moving_max=α⋅max⁡batch+(1−α)⋅moving_maxmoving_min=α⋅min⁡batch+(1−α)⋅moving_min\begin{aligned} moving\_max &= \alpha \cdot \max\nolimits_{batch} + (1-\alpha)\cdot moving\_max \\ moving\_min &= \alpha \cdot \min\nolimits_{batch} + (1-\alpha)\cdot moving\_min \end{aligned}moving_maxmoving_min​=α⋅maxbatch​+(1−α)⋅moving_max=α⋅minbatch​+(1−α)⋅moving_min​

α∈(0,1]α ∈ (0,1]α∈(0,1]：更新系数，典型取值 α=0.1,0.2α=0.1,0.2α=0.1,0.2

  • ααα 大：快速跟随新数据，记忆短
  • ααα 小：更平滑，记忆更长

注意⚠️：这不是普通 EMA（对值加权平均）！是对极值做指数平滑，不是加权平均激活值，很多人容易混淆。 TensorRT / TorchAO 流式校准里会见到这个变种。

Percentile 百分位校准

在minmax的基础上进行改进，不再直接使用tensor中的最大最小值来表示t，而是通过某种方法来筛选掉离群点，如乘以一个percentile

KL

  1. 收集激活值，统计浮点原始分布直方图 P
  2. 尝试一系列截断阈值 TiT_iTi​，把大于 TiT_iTi​ 的值全部归到直方图最后一个 bin，得到截断后的分布 Q
  3. 计算原始分布 P 和量化后分布 Q 的 KL 散度 DKL(P∣∣Q)D_{KL}(P||Q)DKL​(P∣∣Q)
  4. 选出使 KL 散度最小的阈值 T，作为最佳截断点

DKL(P∣∣Q)=∑P(x)log⁡P(x)Q(x)D_{KL}(P||Q)=\sum P(x)\log\frac{P(x)}{Q(x)}DKL​(P∣∣Q)=∑P(x)logQ(x)P(x)​

KL 散度衡量两个分布之间的差异，越小说明量化后分布越接近原分布。

优点

  • 自动权衡：截断一部分少量离群点，让主体分布量化误差最小，对 LLM、Transformer 效果很好，TensorRT 默认推荐。

缺点

  • 需要遍历候选阈值，多次计算 KL，速度慢
  • 依赖直方图 bin 数量；直方图 bin 太少结果不准
  • 假设分布形态，某些双峰分布不一定最优
  • 只关心分布形状，不完全等价于最终推理损失
